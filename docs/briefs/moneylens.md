# 工具 · MoneyLens（moneylens）

对话名「工具 · MoneyLens」。网址：介绍页和工具页卡片在 changle.ca/tools/finance，应用在 money.changle.ca（都还没上线）。档案建于 2026-11-18；以后由这个对话维护。

## 它是什么

个人记账整理工具：把银行网站导出的账单（CSV、OFX/QFX，以后加文字版 PDF）在自己手机或电脑的浏览器里解析，对账、去重、分类，看花销、现金流、订阅、预算。用 changle.ca 的账号登录，每个人的数据只有自己能看。不限银行：谁的银行给的账单都能传（Steve 2026-11-19 定的）。MoneyLens 是暂用名；中文名先用「心里有数」（问过 Steve，他回了「可以」但没说选哪个，先用这个，他说换就换）。

要求全在 [`docs/moneylens.md`](../moneylens.md)（v2，英文，447 行）。它里面的编号（`ISO-2`、`VAULT-4`、`T-9` 这些）代码和测试里直接引用。它没写功能细节：最早的功能说明和 v1 不在仓库里也不在 Project 文档里（见「等 Steve 的事」）。

和别的工具最不一样的三点，动手前记住：

1. **真实财务数据永远不进仓库、CI、截图、PR 文字、日志和任何 AI 工具**（SEC-12）。测试只用合成数据。
2. **上线靠闸门，不靠憋着不合并**（SEC-10）。合并照常部署，但所有功能挡在服务器的允许名单后面，每过一个阶段由 Steve 开闸，日期记在这里。
3. **登录、会话、加密、同步、权限的改动，合并前要有一份不是作者本人的审查记录**（另一个模型或人，SEC-9），写在 PR 里。

- `npm run typecheck`

这个对话定的做法（Claude 定，写代码时会回来对一遍；Steve 或审查的人可以改）：

- 名字和目录：代码在 `tools/moneylens`，Worker 叫 `moneylens`，工具 id 是 `finance`（跟网址走，改名不用动）。
- 主站只放介绍页和卡片，不带任何财务代码（ARCH-1）。演示在 `money.changle.ca/demo`，用合成数据，不用登录。
- 会话不用密钥：Cookie `__Host-ml` 里是「账号 id + 256 位随机数」，账号 id 只用来找到这个人自己的 Durable Object，认的是随机数（库里只存它的 SHA-256）。猜不出随机数就进不去，所以符合 ISO-2。闲置 30 分钟、最长 12 小时。
- 同步不开 WebSocket：解锁后、导入后、回到页面时各发一次批量请求，平时最多一分钟一次（每次改到块都算进每天 300 次写入）。一批里的块要么全写进去要么全不写：有一个不是照服务器现在那份改的，整批退回，回信里带着服务器现在那几份，设备合并后再发。所以一次导入要么整个在服务器上，要么整个不在。
- 分块（2026-11-21 定，取代原来「一个加密的根块记哪个月在哪个块」的想法）：**没有根块**。每个块自己在密文里写着它是哪一组的（`book`：账户、导入记录、规则、预算、设置；`t/<账户 id>`：这个账户的交易）。新记录放进同组里还有空的块，满 240 条就开新块。分组只决定「谁跟谁放一起」，对错不靠它：记录按 id 找，进了服务器以后不搬家。这样没有哪个块是所有设备都要抢着改的，两台设备各建了一个同组的块也没事（都读）。服务器看得到的还是只有 id、大小、版本号、时间。
- 合并规则：拿「两边共同的起点、这台设备的、服务器的」三份逐条比。只有一边改了的，留那边的；两边改了同一条的不同字段，都留；两边把同一个字段改成了不同的值，钟晚的那边赢，并告诉页面；一边删了，就是删了，另一边的修改跟着丢，也告诉页面。谁来合并结果都一样。钟只在「同一个字段两边都改了」时才看。
- 回信丢了怎么办：发出去没收到回信的那一份留着（`sent`），下次这个块还发**同一份**，直到有回信说清它的下落（原样在服务器上；在服务器上而且别的设备已经接着改了，这由块里自己记的「我是从哪几版来的」认出来；或者块已经往前走了、它永远进不去了）。不这样做的话，在那份里加过、后来又删掉的记录会回来。超时的请求可能在设备「看过服务器、没看到」之后才到，所以没有回信之前什么都不假设。
- 写入要报「我是照哪一份改的」：版本号加那一份的记号（封块时的随机数，本来就明文放在块头上）。只报版本号不够：服务器从备份恢复以后会从旧号码接着数，把同样的号码发给别的内容。
- 服务器的那份倒退了（恢复备份、故障、或者有人作恶）：同步过的设备下一次同步就会发现（它以为服务器有的和服务器实际有的对不上；它有的块没了；新的一份不是接着它那份改的），然后**停下来、说出来、两边都不动**。现在的出路只有一条：这台设备改用服务器那份（先让用户导出，再清掉缓存重新来）。「把这台设备的那份送回服务器」还没做，已经定了要做成两边的记录都留（代价是只在一边删掉的记录可能回来）。没同步过的新设备发现不了，这是写明的短处。
- 缓存里只有密文和版本号。改动先在内存里，`flush` 封好写进缓存（页面要在改动后一秒左右做一次，切到后台时也做），`sync` 才发。
- 加密（详见 `docs/moneylens/security-assessment.md`）：内容用 AES-256-GCM，一个保险库一把钥匙，每次封块一个新的随机数；钥匙用 AES-KW 包装，每种进门方式一个包装；口令用 PBKDF2-HMAC-SHA-256 跑 60 万次（OWASP 现在给的数，2026-11-19 查的）变成包装钥匙，恢复码和通行密钥用 HKDF。保险库的 id 和包装的种类都参与生成包装钥匙，所以服务器把包装改成别的保险库的，就打不开。选 PBKDF2 不选 Argon2id：它是浏览器自带的，不用引第三方的 WebAssembly，安全策略能保持最严；以后要换，只是给同一把钥匙多做一个包装，不用重新加密。
- 口令怎么算「同一句」：手机会把直引号变弯引号、两个连字符变破折号，中文输入法会打出全角字母和「。」，这些都折回去再算钥匙，这样桌面和手机打同一句话得到同一把钥匙。顺序是先把全角半角折成普通字符（NFKC），去掉看不见的字符（变体选择符、零宽空格、从聊天软件或文档里复制时带出来的方向标记等；连接 emoji 用的零宽连接符保留）再做一次 NFKC，然后折标点：各种语言的引号和撇号（弯引号、« »、「」『』）都折成直的；人名中间的点（中文、日文、繁体输入法打出来的三种）折成一种；日文键盘的波浪线折成 `~`；**任何横线、连着的几个横线都算一个连字符**（两个连字符在手机和 Word 里变成长破折号，在 Google Docs 里变成短破折号，三个又不一样，所以 `a--b`、`a-b`、`a—b` 是同一句，算长度时一串横线只算一个字符）；「。」折成「.」。折两遍和折一遍结果一样。中文输入法在中文状态下把某些键打成别的符号（`<` 打出《、`$` 打出￥、`^` 打出……），那是另一个字符，不折。大小写不折，所以以后口令输入框必须关掉自动大写和自动更正。**这套折法是钥匙的一部分，定了就不能改**（改了老用户就进不去），要改只能出新版本的包装并且继续认旧的。
- 口令的底线：至少 12 个字符（其中有 4 个以上中日韩文字时 8 个）；不能是重复、键盘顺序（三个键一段的 `123qweasdzxc`、按着 Shift 打的、两条顺序交叉打的都算）、中文数字顺序；不能是不到 20 位的纯数字，也不能是「一长串数字占了三分之二以上，前后带几个字母」（姓名缩写加生日）；不能主要由常见密码和常用语组成（占到三分之二就算；换字符、加重音、倒着写、中文常用语都算）；不到 20 个字符时不能只是一两个词加数字和符号（`Maplewood2026!!`，把字母换成数字的 `M4plew00d2026!!` 也认得出），三个词可以。建保险库和改口令的函数自己查，页面绕不过去。
- 底线怎么认「词」：代码里没有词典。一段字母能从头到尾拼成拼音，或者长得像英文词（有元音、没有四个辅音连着（th、ch、ng 这类算一个）、相邻字母是英文里常见的搭配），就算一个词。常见搭配表是从 SCOWL 英文词表算出来的（676 种里的 305 种）。这是个粗办法，**两头都会错，是故意的**：密码生成器出的随机串基本放行（12 位大小写加数字误拒 0.4%，14 位小写加数字 2.7%，改之前是 60% 和 21%）；「能念出来」的那种生成器（辅音元音交替）是例外，不到 20 个字符时一半会被拒；词里有英文少见的字母搭配就认不出（`blue sky 2026` 会放过去），人名也认不出（`Chloe2026!!!`）。数字都记在安全评估 1.4。它是底线，不是强度计；审查建议到做口令页面时再叠一个成熟的估算器（zxcvbn-ts），到时评估。
- 恢复码：160 位随机，8 组 4 个字符，后面再带 2 个校验字符。抄错一个字符或相邻两个抄反，能认出来是「抄错了」，不会和「这不是你的恢复码」混在一起；少一个或多一个字符是「长度不对」。组之间用空格、各种横线、点、下划线都读得出。
- 迭代次数三个数：新包装按 `PBKDF2_ITERATIONS` 写，指引提高时改这个；`PBKDF2_FLOOR` 是存下来的包装最少要有的次数，**永远不能调到比真实保险库写过的最低次数还高**，不然那些保险库就打不开；上限 200 万，防服务器塞一个大数让手机卡死。
- 改口令是给同一把钥匙做一个新包装、再删旧包装，内容不重新加密。所以旧包装如果早被人拷走，旧口令还能打开那份拷贝；担心旧口令泄露的人，第一版的办法是导出、清空、重新导入。
- 解锁失败要说清是哪种：这个版本的应用读不了这份包装（应用太旧或者格式不对）；这份包装是别的保险库的（手机记着自己该开哪个保险库，对不上就直接报，不试口令）；或者没打开。**「没打开」不等于口令错**：包装里的保险库编号、盐、次数或者钥匙被人改过，表现和口令错一模一样。所以以后的页面不能因为解锁失败就告诉用户「保险库没了」，也不能因此引导他去重置；重置留在 VAULT-5 说的地方，由确实丢了口令的人自己选，还要过 VAULT-7 的 7 天。做同步时手机要记住保险库编号，最好再记一份包装的指纹。
- 不按银行写解析器，按格式写读取器（Steve 定了所有银行都支持）。OFX/QFX 是通用格式，一个解析器。CSV 各家版式不一样，`anycsv.ts` 从文件本身认版式：表格从哪一行开始、有没有表头、哪列是日期、日期是月在前还是日在前、钱在哪列（一列带正负号、支出收入两列、或者金额旁边一个说方向的词）、哪列是每行之后的余额。**余额能从金额一行行推出来，是文件能给的最硬的证据**：它定正负号、定先后顺序，也让导入能对账到分。保存之前有两道闸：预览（IMP-6）和对账（ACC-2）。哪家银行的 CSV 通用读取器读错了，还可以给它单写一个解析器登记到 `CSV_PARSERS`，会先试它。
- 读取器宁可拒绝，不替用户挑。两种读法都说得通、文件里又没有东西能分出来时，返回 `layout-unclear`：页面把表格给用户看（`csvPreview`），用户指出哪列是什么，再用 `readCsvAs` 读。只有两件事它会先假设、同时说出来：日期的月日顺序（`date-order-guessed`，整份文件没有一天超过 12 号时就分不出来）和钱的方向（`sign-guessed`）。这两个不是提示，是要问用户的问题；用户的回答改的是版式里的一个字段，然后重新读。
- 账户类型要页面告诉读取器。信用卡的文件和银行账户的正好反着读（消费让欠的钱变多），文件自己很少写明是哪种。不告诉它，它按银行账户读，返回的账单里不带类型；用户说是信用卡以后，要从头重新读一遍，不能沿用刚才认出来的版式。
- 版式确认以后跟账户存在一起，下次同一家银行的文件直接按它读，不再假设。表头改了名或者列数变了，旧版式不硬套，重新认。
- 夹具工具做成「账单试读」页面（2026-11-20）。Steve 用它在自己电脑上看真账单读得对不对，同时它把真账单变成两样可以发出来的东西：**编出来的版本**（版式和原文件一样，字和数字全是编的）和**摘要**（只有版式，没有任何内容）。真账单哪儿也不去：页面是一个文件，里面带着全部代码，策略里禁止一切联网（T 里没有这条，是 SEC-12 的做法）。
  - 编的规则：字母换字母、数字换数字，长度、大小写、标点、小数点位置都不变。账单用词（Balance、Withdrawals、Solde、余额这些）原样留着，因为读取器要找它们，它们也不是谁的数据。年份留着。月份整体挪同样的月数（不绕过年底，不然先后会乱），日子按原来的先后挪到别的日子，12 号以内的还在 12 号以内（这是读取器分月和日的依据）。整数金额不留成整数。
  - 表头那一行原样保留（要靠它认识各家银行的列名）。页面把这一行单独显示出来让 Steve 看：万一没有表头、第一行被当成了表头，里面可能有名字。
  - 现在编出来的数字是一个一个编的，所以余额那一列和金额对不上了（读取器会把这样的余额列丢掉，说「没有余额」）。要让编出来的版本账还对得上，得靠读取器对版式的理解重新算一遍余额，是这个工具的下一步。
  - PDF 现在只抄版式（每段文字在哪个位置、写成什么样），还读不成交易。先收集真账单的版式，再照着它们写 PDF 读取器：没有真版式就写，写出来的多半只认我自己编的样子。所以顺序改了，夹具工具在前，PDF 读取器在后。
  - 页面从文件打开时，Chrome 不让用「模块」方式从一段文字启动 Worker，所以 PDF.js 的 Worker 先包成普通脚本再放进页面（`scripts/build-check.mjs`）。
- 通用 CSV 读取器现在知道的短处。每一条都会在预览里看出来，或者直接拒绝，不会悄悄读错；也都还没拿真账单核对过，那是 Phase 2 的事：宽度和表格不一样的行不算交易（行尾的空格子被省掉的文件会被拒绝）；两位数年份写在最前面的日期（`26/10/05`）拒绝；没有表头时，账号那一列要在很多行里重复出现才认得出来；一份信用卡文件里有两个卡号会被分成两份账单；一个文件里有好几个账户时，正负号只能用同一条规则；信用卡如果大部分时间是多还了钱，会读反。
- 正负号全站统一：进账户的钱是正数，出去的是负数；信用卡欠 400 元，余额是 -40000（`money.ts` 开头）。
- 日期照银行写的那一天记，不换时区。OFX 的日期只取前八位，后面的钟点和时区不看：各家银行在后面随便填午夜或中午，换算会让有些银行的账往前挪一天（`dates.ts` 的 `ofxDay`）。
- 去重不单凭银行的流水号（FITID）：有的银行每个文件都从 1 编号，所以流水号一样还要同一天、同金额才算重复。一个文件里自己重复的行不删。拿不准的列成「可能重复」给用户看，不自动丢（`dedupe.ts`）。
- 转账配对要金额相同、不同账户、同币种、相隔 5 天以内，而且至少一边的文字像转账。两边都像才自动配，只有一边像就只是建议。光金额一样不配（`transfers.ts`）。
- 自动分类不存在交易上，每次现算，所以加一条规则会改到过去的交易，删掉规则就恢复原样。只存用户自己选的分类和 AI 的建议（`classify.ts`）。
- 另一种货币的交易（OFX 的 `<CURRENCY>`）没有本账户货币的金额，MoneyLens 不换汇（ACC-6），先跳过并提示，等有真实样本再定怎么显示。
