# 工具 · 两清（split）

对话名「工具 · 两清」。网址 changle.ca/split（第一期的小样上线了，先藏着：工具页上没有入口，知道网址才打得开，账本只存在打开它的那部手机上）。档案建于 2026-11-12；以后由这个对话维护。

## 它是什么

两清 · All Square：分账工具。一群人出去玩，谁付了什么记一笔，最后告诉每个人该给谁多少钱。发一条链接就能加入，不用先注册；开账本的人要登录，账本存在云端，每人 500 MB 放小票照片。网站不碰钱，转账大家自己用 e-Transfer 或微信。完整方案在 [`docs/split.md`](../split.md)。

## 测试

- 算账：在 `site` 里 `npx tsx tests/split.test.ts`（约 12 秒），CI 的 `site` 任务跑它。它查：打的字和分之间来回不走样；方案里的每个例子；尾差轮流（300 顿 $100 三人平分，每人正好多付 100 次）；一笔花销哪里不对；线框图上那个示例账本（净额、4 笔转账、点已转、撤销、结清后又记一笔）；结清的笔数和「每种转法都试一遍」一样（4,000 组 2 到 8 人）；1 万个随机账本，每笔分完加起来等于原价、净额加起来是零、照方案转完每个人归零、一步一步付的时候方案不变；最后一条是前 2,000 个账本结果的指纹，规则一改它就变，要改得是故意的。
- 算账再算一遍：在 `site` 里 `npx tsx tests/split-second.test.ts`（约 12 秒），CI 的 `site` 任务跑它。Codex 只照卡 C1 上的规则另写了一份算账（`tests/split/second.ts`，写完单独提交以后才看的 core），在同一批 1 万个随机账本上和 core 逐项对比：158,330 笔花销每个人各摊多少、1 万个账本的净额、8,624 个账本的最少转账笔数（还没归零的人不超过 12 个的那些）、1 万份结清方案照着转完每个人归零；最后是两个手算的小账本（删除时间是 0 的一笔花销、一笔已转）。两份对不上，就是其中一份错了：照卡上的规则在最小的账本上用手算，看是谁。
  - 两份要一直是两个人写的。规则故意要改的时候，core 这边改，`second.ts` 写一张卡让 Codex 照新规则改，不要自己照着 core 改它。
  - 它查得出错：故意把 core 改坏四种（尾差不看轮到谁、已转算反了方向、结清不是最少笔数、按份数四舍五入），每一种它都红。
- 画面的规则：在 `site` 里 `npx tsx tests/split-screens.test.ts`（1 秒），CI 的 `site` 任务跑它。它查：数字键盘每按一下金额读成什么（随机乱按 4,000 轮，屏幕上永远是个金额）；钱怎么写（11 种货币，复制金额复制出来的就是那个数）；记一笔填到一半的每种情况，三种分法之间来回换；400 个随机账本里的 4,000 多笔，打开不改直接存，谁的钱都不动；对账本的每个改动和每个不让做的改动；方案里那个周末照着画面的做法记一遍（你该收 $42.50、4 笔转账、复制到群里的那段字）；存在手机上的那一份读坏了也不崩；每句文案中英文都有、空位一样、没有没用上的；样式只用 token；最后一节查两清还藏着。
- 在浏览器里走一遍：先 `npm run dev`，再 `npx tsx scripts/split_check.ts`（约 7 分钟；`walk`、`fits`、`behave` 可以单跑）。`walk`：中英文各在 4 种手机大小上把 37 个画面走一遍，每个拍图、跑 axe、查有没有超出屏幕宽、有没有小于 44px 的按钮。`fits`：记一笔在 7 种真手机的高度上一屏放得下。`behave`：后退键、链接、刷新、两个标签页、浏览器不让存东西、没有剪贴板、键盘、三个动效。本地的浏览器用 `CHROME=/usr/bin/google-chrome`。

## 定过的事

- 2026-11-12 Steve 定的：
  - 名字两清 · All Square，网址 changle.ca/split。网址上线后不再改。
  - 开账本要登录，加入不用登录。登录用主站的账号（邮箱验证码），不另做一套。
  - 先后顺序：先定的是排在约时间后面；当天晚些时候 Steve 说「开工吧」，两清不等了，和约时间各做各的。
- 方案里写定的（细节和理由在 `docs/split.md`）：
  - 不经手钱：不接支付，不存银行卡，收款方式只展示。不放广告，不限笔数，不卖会员。
  - 第一版：开账本、链接或二维码加入、记一笔、三种分法（平分、按份数、按金额）、多币种（站内的 11 种）、净额、最少转账的结清、改和删留记录、同步和离线、小票照片、结清图和 CSV。
  - 钱按「分」存成整数。除不尽的几分钱按名单顺序一人一分，下一笔从下一个人开始。结清 16 人以内算真正最少的方案，更多人用近似算法。
  - 画面放在主站里，不像随便那样做成独立应用。只有三屏：账本、记一笔、结清；一屏一个主按钮；灯光是工具的琥珀色。
  - 一个账本最多 30 人；邀请链接是一长串猜不到的字符；每个账号每天最多开 10 个账本。
  - 账本一律存在服务器上，手机上那份只是副本；离线记的每笔在手机上就有自己的编号，补传两次服务器也只认一次。
  - 分三期：算得对、一起记、存得住。每期做完就合并，入口先不放出来；三道验收门都过了才上工具页。
  - 分工：算账、服务器、同步、额度、三屏的样板归 Claude；第二份结清算法、按样板铺开的画面、文案表、CSV、分享图、截图测试归 Codex。
- 这个对话定的算账细节（2026-11-12，方案没写到这么细；代码和卡 C1 都按这个）：
  - 尾差：每个人先拿自己那份向下取整，剩下的几分钱按名单顺序一人一分，从「轮到的那个人」开始。每发出去一分钱，轮到的人往后挪一位；一笔花销记下的时候轮到谁，就存在这笔上（`rot`），以后改别的账、删别的账都不动它。按份数也是这样分尾差，份数大小不影响谁拿那一分。
  - 名单顺序就是成员加进来的顺序，不变。分法里人名的先后不算数。
  - 删掉的账不算钱，但还占着它那一轮，所以删一笔、恢复一笔，别人的那一分钱不会挪。
  - 一笔账删没删，看它有没有记下删除时间（`gone`）：记了任何一个数都算删掉，0 也算；没有这一项才算没删。（2026-11-13 改的：原来 core 把 0 当成没删，是 Codex 的第二份算账查出来的。）
  - 一笔最多 99,999,999.99（日元是 9,999,999,999）；份数是 1 到 999 的整数；「已转」的金额可以比一笔花销的上限大。
  - 换汇：汇率按写下来的数字一位一位算（不用小数近似），半分进一。花销存的是折好的结算货币金额，原币和汇率只是备查。
  - 结清方案只按花销算；点「已转」是给方案里那一笔打勾。这样一个人付了以后，没付的人看到的方案不变，和发到群里的结清图对得上。转过的钱对不上方案里任何一笔时（结清到一半又记了新账），方案改成只管现在还欠的，转过的另外列出来。
  - 结清先把正好相抵的两个人配成一对（这一步不会多出转账），剩下还没归零的人在 16 个以内就算真正最少的；超过 16 个再把正好相抵的三个人配掉，剩下的人够少就照样算最少，否则当一组结。同样的净额在哪部手机上都出同样的转法，并列时名单上靠前的先。
- 这个对话定的画面细节（2026-11-12，线框图没画到这么细）：
  - 小样的账本存在手机自己的存储里（`localStorage`，键 `changle.split.v1`），哪儿也不传。账本号是手机自己生成的 22 位随机串，就是网址里那一段。
  - 琥珀色只用在三处：每屏那一个主按钮、选中的东西、两清的章。金额对不上不用红色也不用琥珀色（`docs/DESIGN.md`：工具的琥珀色和警告是同一个色），用加粗的白字加一个图标。删账本的确认按钮是红的（共用的 Button 自己写明的用法，个人页删账号也是这样）。
  - 动效只有三个：新记的一笔落进列表、「你该收」的数字滚到新的值、最后一笔标成已转时盖上两清的章。减弱动效时都只是淡入。
  - 记一笔一屏放完，不滚动。键盘的键高跟着屏幕剩下的高度走，44 到 56；网页高度 640 以下金额小一号、不写货币名、三行收紧；535 以下（很老的小手机、手机横过来）才变成普通的可以滚的页面。
  - 为什么按不了「记好了」，写在「分给谁」那一行上，带一个图标：在哪儿改就写在哪儿，不另占一行。
  - 「你该收」和金额是一句话分两行，都用标题字体，不是小灰字顶着一个大数字。
  - 切到「按金额」的时候，每个人的数就是刚才那种分法分出来的数，那一分钱的尾差也落在同一个人身上，不重新平分一遍。
  - 成员弹层里一行就是一个名字，点开才有改名、这是我、去掉。记过账的人去不掉，账本至少留两个人，自己去不掉。
  - 空账本只说一次「还没有账」；「结清」里还没有账的时候，底下的按钮也是「记一笔」。
  - 复制到群里的结清方案写真名，不写「你」：在群里看的人不是复制的人。
  - 英文里三种分法叫 Evenly、Shares、Amounts（320 宽的手机上一行放得下）。
  - 小数点认逗号（手机设成法语时数字键盘打出来的是逗号）和中文句号。
  - 没写备注的那一行写「没写备注」；行上先不显示日期。等 Steve 用过再定。
