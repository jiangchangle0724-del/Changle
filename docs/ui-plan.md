# changle.ca UI 与交互优化方案

2026-11-01 · Steve Jiang

今晚我用无头浏览器把 changle.ca 在手机和桌面尺寸上逼真渲染了一遍，跑了 Lighthouse 和 axe 无障碍审计，读了全站 CSS。结论：站已经有专业底子（性能 89、无障碍 94、56 个设计 token、减弱动效有处理），真正拉开「专业级」差距的是六件事：统一（/eat 和主站是两个产品）、层级（17 张彩虹卡一样响）、路由（所有页面都是同一个网址）、中文字体（没指定）、桌面和电视（手机布局直接放大）、性能预算（主线程 4 秒）。下面按证据、方案、验证、分工的顺序写。

## 老手会做而你没要求的事

做过产品设计的人接到「彻底优化」四个字，第一反应不是换皮，而是先定这些：

1. 先定「专业」的标准再动手：三条就够。一致（任何页面一眼认出是 changle）、可读（3 米外的电视和 390 宽的手机都读得清）、可信（点什么都有反馈，错了有退路）。每个改动都要回答它改善了哪一条。
2. 一套设计系统，三个地方用：主站、/eat、未来所有游戏（一起跳、打碟、玩什么）都从同一份 token 和组件出发。不然每做一个新东西就多一套风格。
3. 克制颜色：17 张彩虹卡每张都在喊。老手会让颜色表达意义，比如按类型分 5 个色相（喝酒局、动脑、动身体、线上、工具），而不是按位置分 17 个。
4. 层级先于美化：首页第一屏要回答「我们几个人，现在玩什么」，而不是把 17 个选项平铺。推荐、最近玩过、按人数筛选，比再好看的卡片更专业。
5. 每个页面一个网址：能分享、能后退、能被搜到。这一条改完，网站才从「一个 App 壳」变成「一个网站」。
6. 中文排版单独对待：指定中文字体栈、中文行高 1.6 到 1.7、中英混排的间距、标点挤压。中文用户是主力，却是现在唯一没被设计过的部分。
7. 状态设计：空状态（还没加人）、加载（骨架屏）、错误（断网、验证码过期）、成功（碰杯动效）。现在只有空状态做得好。
8. 性能预算写成数字并每次构建检查：首页 JS 不超过 200 KB，主线程阻塞不超过 200 毫秒，Lighthouse 性能不低于 95。超了构建失败。
9. 真人测试再定方案：找 5 个没用过的人，任务是「现在 4 个人，60 秒内开始玩一个游戏」，看他们卡在哪。设计改动排序以此为准，不以我们的审美为准。
10. 视觉回归测试：Playwright 每次改动截图对比，改一处不会悄悄坏另一处。17 个游戏手工点不过来。

## 设计系统

不推倒重来。现有 56 个 token 是好底子，要做的是收紧、补缺、写成规范文件 `site/src/styles/tokens.css` 加 `DESIGN.md`，三个产品共用。

| 层 | 现状 | 改成 |
| --- | --- | --- |
| 字体 | 拉丁：Figtree 正文、Unbounded 标题；中文未指定 | 保留两套拉丁字体；中文栈定为 `"PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", sans-serif`，不自带中文字体文件（太大）；标题中文用系统粗体加 Unbounded 做英文副标 |
| 字号 | 29 种 px 值 | 7 级尺度：12 / 14 / 16 / 18 / 22 / 28 / 40，加一级电视用 64；正文 16，中文行高 1.65，英文 1.5；用 clamp 在 370 到 1440 之间平滑 |
| 颜色角色 | 12 个 gel 彩色加夜色底，卡片按位置随机配色 | 底色、面板、文字、线、强调（紫）、成功、警告、危险各一个语义名；gel 彩色收成 5 个类型色：喝酒局 coral、动脑 violet、动身体 lime、线上 aqua、工具 amber；卡片按类型取色，同类同色 |
| 间距 | 散落 | 4 的倍数：4 / 8 / 12 / 16 / 24 / 32 / 48，页面左右留 16，卡片内 16，区块间 24 |
| 圆角与层次 | r-small / r-tile / r-panel / r-sheet 已有，阴影 116 处手写 | 圆角保留；阴影收成 3 级：平、浮、弹层；玻璃模糊只用在弹层和顶栏，不超过 2 处同屏 |
| 动效 | 19 组关键帧，缓动 token 2 个 | 动效规范：进场 200 毫秒、离场 150、强调 400；缓动只用 ease-out 和 ease-pop；每个动效回答「它告诉用户什么」，答不上来就删；减弱动效时全部换成淡入淡出 |
| 组件 | 按钮、卡片、弹层、标签、输入框各有写法 | 定 12 个组件并各写一页：Button（主、静、危险、图标）、Tile、Sheet、Tabs、Pill、RosterChip、OTPInput、Toast、EmptyState、Skeleton、GameHeader、PenaltyCard |
| 图标 | 卡片水印线稿风格统一 | 保留这套风格，补齐所有游戏和工具的图标，规格 24 和 48 两档 |
| 触控 | 两处小于 44 | 所有可点元素最小 44×44，密集处用 48 |

写法上：token 只在 `tokens.css` 定义，组件只引用 token，页面只用组件。审查时 grep 到裸写的 hex 或 px 字号就打回。

## 首页与导航

首页第一屏要回答一个问题：我们几个人，现在玩什么。现在它回答的是「这里有 17 个游戏」。

**层级，从上到下**

1. 今晚的人：保留在最上面，但空状态改成一句话加一个大按钮「加上今晚的人」，加完后变成头像排成一行，人数直接影响下面的推荐。
2. 现在玩这个：根据人数和上次玩的，推 1 个大卡（横幅尺寸）加「转一个」。第一次来的人看到的是「4 个人，先来一局真心话大冒险」。
3. 筛选条：喝酒局 / 不喝酒 / 动身体 / 线上 / 需要道具，加人数。筛选是芯片，不是下拉。
4. 全部游戏：卡片按类型取色（见设计系统），同类同色；卡片上多一行信息：时长和是否要喝酒；「新」标签 30 天后自动消失。
5. 工具和心愿单：保留三个 tab，但「工具」里的随便、玩什么要穿和游戏卡同一套卡片样式。

**每个页面一个网址**

| 页面 | 现在 | 改成 |
| --- | --- | --- |
| 首页 | / | / |
| 游戏介绍弹层 | / | /g/truth-or-dare（弹层照旧，但地址栏变，后退能关） |
| 游戏进行中 | / | /g/truth-or-dare/play?t=ABCD（联机时带桌号） |
| 工具 | / | /tools，随便保持 /eat，玩什么 /go |
| 设置、登录 | / | /settings、/login（弹层形式不变） |
| 联机桌 | / | /t/ABCD，扫码直达 |

做到这一步，分享一个游戏链接就能直接打开，浏览器后退不会一下退出整个站，Google 能收录 17 个游戏页，每页带标题、描述和分享图。

**桌面与电视**

- 720 以上：两栏，左边今晚的人加联机，右边游戏网格 3 列；1200 以上 4 列。
- 电视（观察者模式）：一个 `?view=tv` 参数，字号用电视档，隐藏所有操作，只显示当前游戏的大屏内容和加入二维码。这和一起跳、打碟的音箱端是同一个东西，做一次。
- 顶部光晕改成跟随滚动的固定层，不再在第一屏底部截断。

**首次体验**

第一次打开：不弹教程，用「现在玩这个」那张大卡当教程。第一次点进游戏弹层时，弹层里多一行「怎么玩」可展开。登录永远不拦在玩游戏前面，只拦在联机开桌前。

**A4 进度（2026-11-02）**：首页从上到下改成今晚的人、现在玩这个（按人数挑一个，不挑刚玩过的，可以换一个）、筛选（全部 / 喝酒局 / 不喝酒 / 动身体 / 线上，加了人以后多一个「适合 N 人」）、全部游戏。游戏卡换成共用组件 Tile，按 Steve 定的 5 类上色（分法写在 DESIGN.md），卡上多一行人数、时长和酒杯；「新」到 `newUntil` 那天自动消失。720 以上两栏，1200 以上 4 列。「需要道具」没做：现在没有哪个游戏要手机以外的东西。还没做：工具页的卡片换成同一套样式、顶部光晕跟随滚动、弹层里可展开的「怎么玩」。

## 游戏内体验：统一的游戏壳

17 个游戏各写各的，专业感是在「壳」上统一出来的。做一个 `GameShell` 组件，所有游戏放进去：

| 壳的部分 | 内容 |
| --- | --- |
| 顶栏 | 返回、游戏名、当前轮次或剩余时间、声音开关、观察者入口；高度固定 56，安全区自动 |
| 玩家条 | 今晚的人的头像横排，轮到谁谁放大，喝了几杯用小点记 |
| 主区 | 游戏自己的内容；壳只保证最小字号和对比度 |
| 底部动作区 | 最多两个按钮，主按钮永远在右手拇指位置；高度 72 加安全区 |
| 惩罚卡 | 全站统一的 PenaltyCard：喝一口 / 做 5 个俯卧撑 / 表演，样式和动效一致 |
| 结束页 | 统一的结算：谁喝得最多、最佳表演，一键再来一局或换游戏 |

状态设计，每个游戏都要过一遍：

- 加载：进游戏先出骨架屏，不空白；超过 2 秒出一句话。
- 断网：联机桌断线显示「重连中」，30 秒内自动恢复不丢进度。
- 验证码过期、桌号不存在、房间满：各一句人话加一个动作，不出英文错误码。
- 声音：音效试听已经很好；加「第一次点击才初始化声音」的处理，iPhone 上不会静音；背景音乐在游戏有自己声音时自动停（你已经要求过）。
- 横屏：壳自动切到横版，玩家条到左侧，主区变宽；你画我猜和到此一游最受益。
- 中途离开：刷新或误触返回，弹一句「这局还在，回来继续？」，进度存本地。

## 一致性：把 /eat 收编

「随便」现在是另一个产品：米色底、红按钮、系统字体、Google 登录、右上角一个 English、页脚隐私政策，没有 changle 的字标，也没有回主站的路。它是主站之外第一个工具，所以它的样子决定了「以后每个工具都长成什么样」。

| 项目 | 现在 | 改成 |
| --- | --- | --- |
| 视觉 | 自己的一套 | 用主站 token：夜色底、工具类型色 amber 做强调；筷子图标保留，作为工具的卡片图标 |
| 顶栏 | 只有 English | 主站同款顶栏：changle 字标可点回首页、语言开关、账号 |
| 登录 | Google 登录 | 和主站一样的邮箱验证码登录，一个账号两边通；Google 登录作为第二选项保留 |
| 文案风格 | 已经很好（「吃什么？随便。那就让大家的手机来定。」） | 保持，这句是范本 |
| 隐私和条款 | 只在 /eat 有 | 搬到主站页脚，全站一份 |
| 代码 | tools/suibian 独立 Worker，独立样式 | Worker 保留；样式改引主站的 tokens.css 和组件包（发成 `@changle/ui`），之后一起跳、打碟、玩什么都从这个包起步 |

原则：新东西可以是独立的 Worker，但不能是独立的外观。

## 性能与技术债

数字来自今晚的 Lighthouse 手机版模拟。目标写进构建脚本，超了就不让合并。

| 项目 | 现在 | 目标 | 怎么做 |
| --- | --- | --- | --- |
| 首页 JS | 482 KB 一个包 | 首页 ≤ 200 KB，每个游戏自己一个包 | 按路由懒加载，17 个游戏各自 `import()`；GSAP 只在字标动画用，改成首屏之后空闲时再加载，或者换 CSS 动画 |
| 主线程 | 4.0 秒，阻塞 420 毫秒 | 阻塞 ≤ 200 毫秒 | 上面那条做完大半就解决；字标逐字动画推迟到空闲 |
| CSS | 96 KB，未用 18 KB | ≤ 60 KB | 游戏样式跟游戏包走；阴影和模糊收成 token 后自然变小 |
| 字体 | 两套拉丁 71 KB，font-display 已处理 | 不变 | 中文不自带字体文件；可以把 Unbounded 只保留标题用的字重 |
| robots.txt | 18 处错误 | 0 | 重写成三行：允许全部、Sitemap 地址、禁止 /api |
| SEO | 全站一个网址，17 个游戏不可见 | 每个游戏一页，带标题、描述、分享图 | 路由改造的副产品；分享图用 Worker 按游戏生成一张 1200×630 |
| 缩放 | user-scalable=no | 去掉 | 游戏内要防误触缩放的，用 touch-action 处理，不动 viewport |
| 缓存 | 15 KB 可省 | 静态资源一年缓存 | Cloudflare Pages 加 _headers 文件 |
| PWA | 无 | 可加到主屏幕，离线能开首页 | manifest 加 service worker，离线缓存首页和已玩过的游戏包；iPhone 上「添加到主屏幕」后全屏，没有地址栏 |
| 监控 | 只有 Cloudflare 的访问统计 | 页面级：哪个游戏被点、玩了多久、在哪一步退出 | Cloudflare Web Analytics 加自定义事件，不加第三方脚本 |

## 原始素材：从源头拿

| 素材 | 为什么是源头 | 怎么用 |
| --- | --- | --- |
| 仓库里的 `site/src` 本身：现有组件、CSS、17 个游戏的代码 | 优化是在它上面做，不是旁边重做 | 开工第一天让 Claude Code 列一张「组件清单加重复写法」表 |
| 5 个真人的首次使用录屏 | 设计排序的依据 | 任务：4 个人 60 秒内开始玩；记录卡点 |
| 你自己的派对录像或照片 | 真实使用环境：灯光暗、手机传着看、电视在远处 | 字号、对比度、按钮大小按这个环境定，不按办公室 |
| Apple HIG 和 Material 3 的触控、字号、动效章节 | 44 点、字号下限、动效时长的行业默认值 | 设计系统的数字从这里取，不自创 |
| WCAG 2.2 的对比度和目标尺寸条款 | 无障碍的硬标准 | axe 跑不出的（对比度 incomplete）人工按它查 |
| 微信小程序设计指南和小红书的信息层级 | 你的用户每天看的界面，习惯从这里来 | 中文排版、卡片密度、标签样式参考它，不参考硅谷 SaaS |
| Jackbox Party Pack 的「大屏加手机」交互 | 这个品类做得最好的产品 | 观察者模式和游戏壳的参照 |
| Lighthouse 和 axe 的原始 JSON（今晚已跑） | 可重复的基线 | 存进仓库 docs/baseline/，每次改完对比 |
| 全站 CSS 的 token 和 29 种字号清单（今晚已抽） | 收尺度的起点 | 映射表：每个旧值对应新尺度的哪一级 |

## 方法与工具

| 环节 | 用什么 | 为什么 |
| --- | --- | --- |
| 设计系统落地 | 一份 `tokens.css` 加 `DESIGN.md`，组件包 `@changle/ui`（React，无第三方 UI 库） | 现有栈是 Vite / React，不引 Tailwind 或 MUI，避免推倒重来 |
| 路由 | React Router 或 TanStack Router，弹层用路由承载 | 每页一个网址，后退可用 |
| 动效 | CSS 动画为主，GSAP 只留给字标和结算页；全部读 token 里的时长和缓动 | 省主线程；统一节奏 |
| 构建预算 | `size-limit` 加 Lighthouse CI，阈值写进 CI | 超了合并不了 |
| 无障碍 | axe-core 跑在 Playwright 里，每个页面一次；对比度人工复查 | 自动化为主 |
| 视觉回归 | Playwright 截图对比：17 个游戏首屏、首页、弹层，手机和桌面各一套 | 改一处不悄悄坏另一处 |
| 中文排版 | `text-autospace` 可用则开，`lang` 按内容切 zh-CN / en，中文行高 1.65 | 中英混排不黏在一起 |
| 分享图 | Worker 用 `@vercel/og` 或 satori 生成每个游戏的 1200×630 | 分享到微信有图 |

**find-skills 结果**：搜了 UI 设计审查、无障碍、React 动效三类。值得装的两个，都是行业里装得最多的：

## 三道验收门与优先级

按证据排门，不按功能排周。每道门过了才开下一道。

| 门 | 证明什么 | 必须过的指标 | 目标 |
| --- | --- | --- | --- |
| A 骨架对 | 设计系统成文，路由能分享，性能预算进 CI | tokens.css 和 DESIGN.md 合并；/g/ 链接微信里点开直达；首页 JS ≤ 200 KB；robots.txt 0 错误 | 第 2 周末 |
| B 首页对 | 新来的人 60 秒内开局 | 真人测试 4/5；Lighthouse 四项达标；中文排版两台一致；触控全部 ≥ 44 | 第 4 周末 |
| C 全站一致 | 17 个游戏和 /eat 穿同一套壳 | 一致性盘点归零；视觉回归 40 张通过；电视 3 米可读 | 第 8 周末 |

优先级（如果只能做三件）：

1. 路由加分享图：从 App 壳变成网站，流量入口从此打开。
2. 首页层级加按类型取色：第一眼的专业感全在这里。
3. GameShell 加 /eat 收编：以后每个新游戏都省一半工，一起跳和打碟直接受益。

不做的：换 logo、换主色、加暗亮两套主题。现在的夜色加紫是对的，别动。
