# 抓紧了 · Hang On 游戏方案

2026-11-02 · Steve Jiang · 在线版（含架构图）：https://claude.ai/artifact/2GighxfKjTt8S9okJqvQtN

你要的是 Heave Ho 那种「两只长胳膊抓来荡去、几个人连成一串、摔死了还笑」的手感，放在手机加电视上，部署到 changle.ca。这个能做，而且我今晚已经把最难的一步做了：浏览器里能玩的手感原型，抓、荡、拽、翻、拉人都成立。但有一条线要先画清：手感、节奏、笑点可以做到一致甚至更好；角色、关卡、美术、名字必须原创，那是 Le Cartel 和 Devolver 的版权。下面是完整方案，按证据、设计、技术、验证、分工的顺序写。

## 哪些能一致，哪些必须原创

| 可以做到一致甚至更好 | 必须原创 |
| --- | --- |
| 手感：两只长胳膊、每只手独立抓、荡、投、拉人成链。这是玩法机制，不受版权保护 | 角色造型（它的圆脑袋加巨手是它的形象） |
| 节奏：一关 1 到 3 分钟，死了秒复活，所有人到终点才算过 | 关卡布局和世界主题（丛林、峡谷、樱花是他们的关卡设计） |
| 笑点：摔死时的尖叫、队友松手的背叛、最后一个人过不去的绝望 | 美术风格、色板、UI、字体 |
| 手套分色辨左右、皮肤解锁、收集物 | 音乐、音效、配音 |
| 局部合作 1 到 4 人 | 名字 Heave Ho（商标） |

工程上这意味着：物理参数、摄像机、操作映射我们可以调到和它一样的「重量感」；美术资产一张都不能拿，关卡不能照着摆。仓库里 LICENSES.md 写明原创，代码和文案里不出现 Heave Ho 字样。

## Heave Ho 的灵魂是什么

2019 年 Le Cartel 做、Devolver 发行，1 到 4 人同屏合作。角色是一个带脸的球加两条长胳膊：两个扳机各管一只手抓不抓，摇杆管胳膊指向。没有跳跃，所有移动都靠抓、荡、松手飞出去。一关就是从 A 到 B，所有人到了才算。摔死很常见，摔死时角色会喊。人可以抓人，连成一串过大坑，或者把队友扔过去。币解锁皮肤。评测公认的好玩点和投诉点：

| 好玩在哪 | 投诉在哪 |
| --- | --- |
| 物理是笑点本身：身体晃、胳膊甩、落点永远差一点 | 死得太多，有些关（滚石）让人想砸手柄 |
| 规则 10 秒讲完，不玩游戏的人也能上手 | 关卡不够多，玩完就完了 |
| 全队过关的成就感，和队友松手的背叛感，两种情绪都强 | 最弱的那个人决定全队进度，会有人被埋怨 |
| 前置提示少，靠身体反馈教学 | 单人玩没意思 |

归纳成四件必须做对的事，也是我们的验收标准：抓要稳（按下就抓上，没有滑手的愤怒）；荡要有重量（摆起来能累积势能，松手飞得远）；死要便宜（一秒复活在路点，切不要全队重来）；人要能抓人（这是全部合作笑点的来源）。

## 我们的版本

**名字**：抓紧了 · Hang On。备选：拉一把 · Pull Together；别松手 · Don't Let Go。

**角色**：糯米团。一个圆滚滚的汤圆身体，两条面条胳膊，手是两只颜色不同的小手套（左蓝右橙，辨左右用）。每个玩家一种馅儿色：草莓粉、抹茶绿、芒果黄、苏打蓝。脸是两个点加一张嘴，表情跟物理状态走：抓住时咬牙，飞起来时张嘴，掉下去时尖叫。站上已有的动漫头像可以贴在汤圆上当脸，这是别人没有的。

**世界**：一张年夜饭桌子。关卡是碗筷、蒸笼、火锅、汤勺、筷子架成的桥、倒挂的蜡烛。草地是绿茶布，深渊是火锅汤，摔进去就是摔死。第二个世界是温哥华：从列治文夜市荡到天车站，抓 SkyTrain 车门、抓 Stanley Park 的图腾柱、抓港湾的水上飞机浮筒。这两个世界都是你的，谁也告不了。

**一局**：2 到 4 人（12 人的聚会分两组轮流，其他人在电视前起哄）。选关、倒数、所有人到终点或者强制 3 分钟到。结算页：用时、摔死次数排行（摔得最多的是「今晚的汤圆」）、谁松过谁的手（背叛榜）。罚则走站内开关：摔死最多的喝，松手害队友的喝。

## 手感原型已经能玩

文档旁边的「抓紧了 · Hang On」页面就是它：电脑上鼠标指方向、Q 和 E 抓，手机上中间拖动指方向、左右两个大按钮抓。一关：过缝、荡绳子、攀岩、到旗子。可以加第二个人（键盘 IJKL 加 U O）拉人。

它的物理是我自己写的位置约束（Verlet）软体，约 300 行，不依赖任何库，所以能在 node 里无头跑。跑了 20 项检查全过：

| 检查 | 结果 |
| --- | --- |
| 静止站在台子上，不抖不沉 | 误差 0.0 px |
| 胳膊朝指向伸，长度不超过胳膊 | 伸出 65 px |
| 抓地往前拽（没有跳跃时的移动方式） | 6 秒前进 139 px |
| 抓住台阶侧面，往上推就翻上去 | 翻上 79 px，手不松 |
| 抓住绳子，按节奏左右发力 | 荡幅 107 px |
| 在地上抓住队友 | 成功 |
| 一个人抓绳子、另一个抓他，当两个人的链吊 3 秒 | 两人都在，胳膊没被拉长 |
| 掉出世界复活在起点，计一次死 | 成功 |
| 所有人进终点才算过关 | 成功 |
| 4 个人乱按 20 秒 | 没有数值爆炸，没有一帧穿进地形 |

调过程中的两个发现，正式版要带过去：

1. 挂着时摇杆要指「身体想去哪」，不是「手指哪」。第一版按物理直觉写成手的方向，结果挂着时往右推身体往左荡，完全反直觉。改成「摇杆指身体去向」之后，往上推就是翻上去，左右推就是荡。
2. 挂着的身体必须有一条「系绳」约束：身体到抓点的距离不超过一条胳膊。没有它，两个人成链时面条会被拉成橡皮筋一路沉到底。这在 Rapier 里就是一个 rope joint。

## 架构：电视是主机，手机是手柄

架构图（在线文档里是图，这里写成一行）：手机手柄页 ──WebRTC 数据通道，同一 Wi-Fi 直连──▶ 主机页（Mac 或 iPad 浏览器，唯一跑物理的地方）──HDMI──▶ 电视。Cloudflare（Pages + Durable Object）只做三件事：发房间码、交换 WebRTC 信令、直连失败时中转输入。

和一起跳、打碟用同一套底座（房间、扫码加入、音箱端页面），多了一样东西：WebRTC 数据通道。打碟和一起跳的指令经 Cloudflare 中转没问题，因为它们不要求毫秒级的反应；抓紧了要求。所以手机和主机在同一个 Wi-Fi 下直连，云端只负责介绍他们认识（信令）和直连失败时的备用中转。

主机是唯一运行物理的地方，手机不预测、不同步世界，只发输入。这样没有任何「两边看到的不一样」的问题，也是 Jackbox 类游戏的标准做法。主机页面跑在 Mac 或 iPad 的浏览器里，Apple TV 自己没有浏览器，只能当显示器。

手机局（11-11 加的，没有电视、没有电脑的时候）：一部手机当主机，跑物理、自己也玩；它每 50 ms 把局面压成一张快照发给别的手机，别的手机照着快照画（只在两张之间匀，不预测、不跑物理），主机还是唯一的真相。细节在 `games/hang-on/CONTRACTS.md`「手机局契约」。

## 延迟预算

从拇指按下到眼睛看到手抓上，每一跳都要算。动作游戏的经验值：总延迟 80 毫秒以内感觉跟手，120 能玩，200 开始有「隔了一层」的感觉。

| 一跳 | 最好 | 常见 | 怎么压 |
| --- | --- | --- | --- |
| 手机触屏采样 | 8 ms | 16 ms | 用 pointer 事件不用 click；按键区域大 |
| 手机 → 主机（WebRTC 局域网直连） | 5 ms | 20 ms | 不可靠、无序的数据通道，只发最新状态 |
| 手机 → 主机（备用：经 Cloudflare 中转） | 40 ms | 120 ms | 只在直连失败时用，屏幕上提示「联机绕路中」 |
| 物理和渲染 | 16 ms | 33 ms | 物理 120 Hz 子步，渲染 60 fps，不掉帧 |
| 主机 → 电视，HDMI 线 | 0 ms | 10 ms | 电视开「游戏模式」关掉动态补帧 |
| 主机 → 电视，AirPlay 镜像 | 100 ms | 200 ms | 压不下去，是协议的编码和缓冲 |

结论：HDMI 线总延迟约 30 到 70 ms，和主机游戏一个水平；AirPlay 镜像总延迟约 130 到 270 ms，能玩但手感差一档，还会把笑点变成愤怒。所以这个游戏建议你买一根 USB-C 转 HDMI 线（二十多加元）把 Mac 接电视；Apple TV 留给一起跳和打碟，那两个用校准步骤就能消化延迟。游戏里加一个「延迟计」：主机每秒 ping 手机，左上角显示每个人的往返毫秒，超过 60 变黄，超过 120 变红，大家一看就知道是谁的手机在用 4G。

## 手机手柄的操作设计

原版是两个扳机加一个摇杆。手机横着拿，两个拇指正好对应两只手，这是这个游戏上手机比其他主机游戏更顺的原因。

| 输入 | 做法 | 为什么 |
| --- | --- | --- |
| 左手抓 / 右手抓 | 屏幕左半、右半各一个大区域，按住就抓，松开就放。区域就是半屏，不是一个小按钮 | 抓是最高频的动作，不能有「没按到」 |
| 方向 | 默认：任一拇指在自己半屏内拖动就是摇杆（按下的位置是中心，浮动摇杆），抓着的时候拖就是荡 | 不用第三根手指，抓和指向合在同一个拇指上 |
| 方向，备选 | 倾斜手机（DeviceMotion，一起跳已经有这套代码） | 有人更喜欢，当设置项 |
| 振动 | 抓上振一下，摔死振两下（安卓；iPhone 浏览器不支持就闪屏） | 触感补视线不在手机上的缺口 |
| 手机屏幕显示什么 | 自己的颜色、两只手的状态（抓住了变实心）、摔死次数、延迟 | 不显示游戏画面，眼睛必须在电视上 |
| 防误触 | 全屏、禁止缩放和下拉刷新、屏幕常亮；横屏锁定提示 | 一局中途弹出通知条就摔死了 |
| 微信里打开 | 微信内置浏览器支持 WebRTC 数据通道，但要实测；不支持就走备用中转 | 大家都是微信扫码进来的 |

手柄页面自己是一个很小的页（不到 50 KB），扫码一秒内打开，这比任何动效都重要。

## 物理与动效

**正式版物理用 Rapier2D**（Rust 编译成 WebAssembly，浏览器里最稳的 2D 刚体引擎，免费开源）。原型的 Verlet 软体证明了手感模型，但跷跷板、滚石、可推的箱子、丢队友这些刚体互动用刚体引擎更省事。

| 部件 | Rapier 里怎么做 |
| --- | --- |
| 身体 | 圆形刚体，质量 1，锁旋转（脸永远朝前），角阻尼高 |
| 胳膊 | 每条 3 节胶囊，转动关节连接，质量各 0.05；肩关节带电机，目标角度 = 摇杆方向 |
| 手 | 小圆形，带一个稍大的感应器（sensor）探测可抓物 |
| 抓 | 按下时感应器里有可抓物就在接触点建一个转动关节（revolute），手能绕着抓点转；松开就删关节。拉人就是关节连到对方的身体或胳膊刚体 |
| 系绳 | 身体到抓点的 rope joint，长度 = 胳膊长，原型里证明必须有 |
| 荡 | 挂着时摇杆方向对身体施力（和原型一样：摇杆指身体去向），外加一个小的切向助力，摆起来三下就能飞 |
| 关卡物件 | 静态碰撞体（平台）、铰接的跷跷板、绳子（一串小刚体加关节）、可推箱子、定时消失的饼干平台、弹簧蜡烛 |
| 步长 | 物理 120 Hz 固定步长，渲染插值；速度过快开 CCD 防穿透 |

**动效清单（juice）**，每条回答「它告诉玩家什么」：

1. 抓上：手套闪一下、抓点冒 4 粒小星、身体向抓点微微一颤、手机振动。告诉你：抓稳了。
2. 身体挤压拉伸：沿速度方向拉长，落地压扁。告诉你：多快、哪个方向。
3. 眼睛和嘴：眼睛看向摇杆方向，抓住咬牙，飞起来张嘴，掉落尖叫。告诉旁观者他在经历什么。
4. 拖尾：速度超过阈值才出现。告诉你：这一下飞得值。
5. 摔死：短暂慢动作 0.3 秒、镜头微抖、尖叫声、其他人脸上出汗。告诉全场：哈哈。
6. 复活：从天上掉到起点，落地压扁再弹起。告诉你：可以继续了。
7. 全员到终点：时间停、纸屑、所有汤圆一起跳。告诉全场：赢了。
8. 队友松手让你掉下去：屏幕上弹一行「×× 松手了」。告诉全场：怒谁。

动效都读同一份时长表，减弱动效模式下去调镜头抖动和闪烁。

## 美术管线

这是 2D 游戏，没有必要上 3D。原版的质感来自手绘线条和平涂色块，我们用自己的路子达到同等质感。

| 环节 | 用什么 | 产出 |
| --- | --- | --- |
| 设定图 | GPT Image 和你已有的 Nano Banana：角色三视图、表情表、两个世界的场景气氛图、道具图鉴 | 统一风格的参考图，不直接进游戏 |
| 角色 | 程序绘制（和原型一样）：圆、曲线胳膊、表情是几条线。因为身体是物理驱动的，程序绘制比贴图更活 | 没有角色贴图资产，换皮就是换颜色和帽子 |
| 场景贴图 | GPT Image 出无缝贴图（绿茶布、木筷子、赤豆沙、汤面），去背景的道具（碗、蒸笼、蜡烛） | PNG 切图进 Pixi 精灵表 |
| 背景 | 三层视差：远景氛围图、中景道具剪影、近景散点 | 每个世界一套 |
| Blender | 只用在一个地方：把道具建成简单 3D 模型后渲染成带光影的 2D 剪影，关卡里转角度复用。不做实时 3D | 道具精灵图 |
| 渲染 | Pixi.js 8（WebGL），纹理图集，粒子用对象池 | 主机上 60 fps |
| 字体 | 沿用站内的 Figtree 加 Unbounded，中文系统字体 | 和站内一致 |
| 音乐 | Lyria 3.5 生成 4 首轻快器乐循环（每个世界两首），存文件不实时 | 4 个 ogg |
| 音效 | ElevenLabs 音效或 CC0 音库：抓、松、摔、尖叫（每个角色一套不同音高）、过关 | 20 个短音 |

美术的验收标准不是「像不像原版」，是「3 米外能不能一眼分清 4 个人、抓点和深渊」。

## 关卡与模式

关卡是 JSON，不是代码：矩形平台、绳子、跷跷板、开关、检查点、终点，每个带位置、尺寸、材质。这样 Codex 能批量做关，以后也能开关卡编辑器。

| 世界 | 关 | 教什么 |
| --- | --- | --- |
| 年夜饭桌 1 到 6 | 1 抓地爬行；2 过缝；3 荡筷子桥；4 攀蒸笼塔；5 绳子（面条）荡过火锅；6 必须两人成链才够长的大坑 | 每关只教一件事，第 6 关逼合作 |
| 温哥华 7 到 12 | 7 夹天车车门；8 图腾柱攀岩；9 水上飞机浮筒（会晃）；10 丢队友过 Lions Gate；11 雨天（抓点滑，要快）；12 全部机关连着来 | 把前 6 关的动作组合 |

关卡规则：每关 1 到 3 分钟；每 20 秒路程一个检查点（原版没有，评测里最大的愤怒来源）；摔死的人从最近检查点复活，或者从一个队友身上「掉」出来（队友按一下召唤）。

模式：第一版只有合作闯关。第二版加「比谁先」（同一关两队赛跑）和「坐不住」（平台慢慢消失，最后挂着的赢），这两个是喝酒局的最爱。

关卡编辑器（第三版）：在手机上拖平台搭关，存到账号，扫码分享给别的桌。这是原版没有、而玩家一直要的东西，也是内容不会玩完的路。

## 老手会多做的事

1. 先做手感原型再做任何美术。已经做了。如果抓和荡在浏览器里不成立，后面全部白费。
2. 输入走局域网直连，不走云。这是这个游戏和站上其他游戏唯一的架构差异，也是手感的命。
3. 说服你买一根 HDMI 线。动作游戏对 AirPlay 的 100 毫秒没有办法，软件压不掉。
4. 检查点。原版被投诉最多的就是死了重来；我们每 20 秒一个，摔死便宜，笑点才留得住。
5. 「摇杆指身体去向」的挂着操作。原型调参时发现的，写进设计。
6. 辅助选项：手套颜色可关（进阶）、自动抓（手碰到就抓，给完全不会玩的人）、关卡慢速模式 0.8 倍。一桌人水平差很多，最弱的人决定大家开不开心。
7. 背叛榜。记录谁松手害谁摔死，结算页公开审判。这是聚会里最好的话题。
8. 观众模式有事做：没在玩的人手机上可以押谁先掉，或者投票让一块平台消失（第二版）。
9. 性能预算：主机页面 4 人加 40 个物体 60 fps，2019 年的 MacBook Air 也要达标；手柄页面 50 KB 以内。
10. 一张延迟表常驻屏幕角落，有人说「卡」的时候知道是谁的网。
11. 关卡数据化，编辑器留口。内容量是这类游戏的寿命。
12. 记录每关的平均用时和摔死次数，调难度靠数据不靠感觉：目标是每关 4 人 1 到 3 分钟、每人摔 1 到 4 次。

## 验收门

三道门，每道不过不往下走。

1. 手感门（A1 合并时）：20 条检查全过；你自己用键盘玩 5 分钟，说得出「比原型好在哪」。过不了就回头调参，不开始美术。
2. 联机门（A2 + A4 合并时）：两台手机当手柄，HDMI 接电视，摄像机实测按键到画面 ≤ 80 ms；关一台 Wi-Fi 再开，5 秒内回来。
3. 聚会门（上线前）：一场真聚会 4 人 12 关，3 人说还想玩，新手第 3 关前学会；grep 为零；两个没玩过的人说不是同一个游戏。
