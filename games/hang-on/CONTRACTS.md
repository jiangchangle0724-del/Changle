# 抓紧了 · Hang On 契约

所有人（Claude Code、Codex、以后的你自己）都按这份来。改契约先改这个文件，再改代码。

## 两条铁律

1. **主机是唯一的真相。** 物理只在主机页跑一份。电视局的手柄页只发输入、只显示自己的状态，不渲染世界。手机局（下面「手机局契约」）里别的手机画的是主机发来的快照：只在收到的两张之间匀，不预测、不跑物理。两边不一致的 bug 在这个架构下不存在，别为了「流畅」把物理搬到手机上。
2. **仓库里不出现原版的名字。** 代码、文案、资产文件名、提交信息、注释里都不能有原版游戏名、工作室名、发行商名（三个词见 `docs/hang-on.md` 开头的法律线，禁词表只放在那里）。机制可以一样，角色、关卡、美术、名字全部原创。CI 的 `npm run ip-check` 对 `docs/` 之外全仓库 grep，为零才能合并。

## 输入契约（手柄 → 主机）

每帧一条，不可靠无序通道（`ordered:false, maxRetransmits:0`），只发最新状态，主机丢弃比已收到更旧的 `seq`。

```ts
type PadInput = {
  seq: number;        // 单调递增
  t: number;          // 手机 performance.now()，用来算往返
  ax: number;         // 摇杆 x，-1..1
  ay: number;         // 摇杆 y，-1..1（上为负）
  gl: boolean;        // 左手抓
  gr: boolean;        // 右手抓
  act?: 'summon' | 'emote' | 'item';   // 偶发动作，可省。手柄连发十几帧保证送到，主机 1 秒内同一个动作只算一次（道具按冷却算）
};
```

`summon`（A3）：摔死还没复活的队友立刻从按键的人身上掉出来。`item`（A9）：用自己带的道具，见下面「道具契约」。

主机 → 手柄只发小包，每 250 ms 一条：`{ color, hands:[bool,bool], deaths, rttMs, phase, direct, teamDead }`，A7 加了玩法的几样，A9 加了 `item`、`itemReady`、`itemOn`、`itemFails`。

## 样子契约（A3）

手柄选的样子 `Look = { hat, glasses, eyes, face, arms, voice }`（可选项和中英名字在 `src/look.ts`），连上房间时和改了之后
经房间发给主机（`LinkMsg { k: 'look', look }`，走可靠的 WebSocket，不走数据通道），主机用 `cleanLook()` 收拾。
手套颜色不能换：左蓝右橙是辨左右用的，袖子也不许用蓝和橙；馅儿色跟座位走。`voice` 是摔下去时的尖叫，`auto` 按座位分六个音高。

## 语言契约（A3）

玩家看到的字中英都有。页面里写死的字用 `data-en`（`data-en-label` / `data-en-ph` / `data-en-title`）标英文，代码里用
`tr('中文', 'English')`（`src/i18n.ts`）。语言先看 `?lang=`，再看自己记的，再跟主站设置，最后看手机语言；主机和手柄各自切。

## 房间契约

沿用 party-base 的房间与阶段机：`lobby → countdown → playing → results → ended`。结算页可以直接 `START` 回到 `countdown`（「下一关」「再来一次」不绕回大厅），`LOBBY` 从倒数、玩、结算都能回大厅。房间码 4 位、最多 6 个手柄 + 任意观众、主机断开 30 秒房间作废。信令走 Durable Object（和一起跳同一个），直连失败 3 秒后自动走中转并在主机屏幕角落提示。

手柄当遥控（11-13 Steve：「手机或者电脑投屏那边不做任何控制，只是提供大屏幕展示」）：手柄经房间给主机发
`LinkMsg { k: 'cmd', c: PadCmd }`（开始、再来一次、下一关、回大厅、换关、换玩法、分不分队），谁发都行，主机照在主机页上点那样做；
一下就换阶段的（开始、再来一次、下一关、回大厅）1 秒里只算一次。主机给每个手柄发 `LinkMsg { k: 'menu', m: Menu }`
（现在哪一步、玩法、第几关和关名、人够不够、结算），变了就发、每 2 秒补一次，都走房间（可靠）。电视局的手柄在大厅和结算时
把摇杆和抓键那块换成菜单；玩的时候顶上有「回大厅」，按两下才算。手机局的结算页下面也有这三个键。

手机局的房间：开房时 `POST /hang-on/api/rooms` 带 `{"hostPlays":true}`。房主自己占一个人和 0 号颜色，手柄最多 5 个、颜色从 1 号起；`RoomView.hostPlays` 让每部手机知道这是手机局。

## 联机桌契约（A15，11-19，房间与联机对话 #654 的约定）

抓紧了在 changle.ca 的联机桌（`/t/桌号`）上能选（`site/src/shared/protocol.ts` 的 `ONLINE_GAMES` 最后一个，桌子那边在 `site/src/party/hangon/link.ts`、`site/src/party/stage/`）。

- 开房的是桌子：桌上有大屏（电视的 `/tv/桌号` 或只看的手机）时主人的手机 `POST /hang-on/api/rooms` 发 `{}`，所有手机去手柄页 `/hang-on/pad/?code=CODE&auto=1&table=桌号`（名字在 `hang-on:name`、语言在 `hang-on:lang`，不出表单），大屏去主机页 `/hang-on/?phone=0&room=CODE&table=桌号`；没有大屏时发 `{ hostPlays: true }`，主人的手机去 `/hang-on/?phone=1&room=CODE&table=桌号`（手机局，自己也玩），别人去手柄页。
- 主机页带 `?room=CODE` 就接管这个房，不自己开（只接管一次，结束以后「再开一个房间」才开新的）；手机局还是电视局听房间的 `hostPlays`，和 `?phone=` 对不上就换过来重开这页。桌上的主机页不出「改成手机局 / 电视局」那个键。
- 一局只有一个大屏：主机页连房间时带一把钥匙（`?role=host&key=…`，按房间码存在 sessionStorage，刷新还是同一把）。主机在线时另一台设备再开主机页（比如只看的手机也点了「打开大屏」）是 `hostTaken`，那页说「这局已经在另一台设备上开着了」，给「回到桌上」；主机掉线了谁都能接。没带钥匙的老页面照旧放行。
- 回桌子（`?table=桌号`）：主机页顶栏「回到桌上」按两下（第一下变红，3 秒内再按）结束这局：发 `END`（所有手柄都收到「这局结束了」），留下 `sessionStorage["hangon.over"]`（大屏上是 `hangon.over.tv`）= 房间码，再回去：手机局回 `/t/桌号`，大屏回 `/tv/桌号`（照藏在人群里）。手柄页加入那页有「回到桌上」，玩的时候顶栏「回桌上」按两下：只是自己走，这局照玩，桌上能「回到这局」。这局结束了（`ended`、房间没了 `noRoom`），手柄页留 `hangon.over` 再过 2.5 秒自己回桌子；主机页同样（被别的设备占着的那页不留记号，回 `/t/桌号`）。
- 状态接口 `GET /hang-on/api/rooms/CODE` → `{ exists, phase: "lobby" | "playing" | "over" }`：倒数、玩、结算都算 playing；主机按了结束、主机 30 秒没回来是 over；没开过、收掉了、闲太久是 `{ exists: false, phase: "over" }`。桌上回来的手机每 8 秒问一次，over 了桌子就收桌。
- 本地验：`site/scripts/hangon_table_check.py`（要本地跑房间服务器、主站和 8792 口的抓紧了，见 HANDOFF.md「Run the site locally」）。

## 手机局契约（11-11 Steve 定的「不要电脑，每人手机上都有画面」）

- 在手机上打开主机页（触屏、屏幕短边不到 600）就是手机局；`?phone=1` 强开、`?phone=0` 强关，大厅里触屏设备有一个键在两种局之间换。
- 房主那部手机照样开房、跑物理、画画面，自己用压在画面上的摇杆和抓键玩（排在手柄后面）。
- 画面快照（`LinkMsg { k: 'snap', s: Snap }`，格式在 `src/net/protocol.ts`，压和拼在 `src/net/snap.ts`）：直连每 50 ms、绕路每 100 ms 给每部手机一张，四个人加机关压成文字不到 2.5 KB。直连走不可靠无序通道，丢了下一张补上。
- 手机收到快照就从「现在画着的样子」匀到新快照，一个快照间隔匀完（比主机晚约 50 ms）；人一下子挪得很远（复活、再来一次）就直接跳过去。匀和收快照用同一个钟（`performance.now()`）。
- 事件（抓、松、摔、过关……）跟着快照走：每件有编号，跟着 6 轮快照走完才拿掉（按轮数，不按时间：房主卡一下也丢不了），手机按编号只放一次。
- 样子名单（`LinkMsg { k: 'cast', c: Cast }`）：谁叫什么、什么颜色、什么样子，以及「你是第几个人」；变了就发、每 2 秒补一次，走房间（可靠）。到了结算页带着结算的数（`Results`），每部手机按自己的语言画结算页。
- 声音：每部手机只放跟自己那个人有关的和大家共有的（检查点、饼干、过关），几部手机放在一张桌上不会一下响四遍。
- 画面那部分（Pixi）进了手机局才下载，不带 Rapier；电视局的手柄不下载它。

## 道具契约（A9，11-13 Steve 定的「开局前选道具」）

- 每人带一样（`src/items.ts`：`freeze` 速冻、`noodle` 拉面、`leaf` 荷叶），手柄页的「道具」对话框里选，记在这部手机上；
  经房间发给主机（`LinkMsg { k: 'item', item }`，和样子一样走可靠的 WebSocket，连上时发一次、改了再发），主机 `Sim.setItem(i, item)`。
  电视局的键盘玩家按 `F` 用、大厅里点「我的道具」换；手机局的房主在大厅里点「我的道具」换，玩的时候抓键上面有道具键。
- 只在闯关和大团队里有（`Sim.itemsOn`）；比谁先、坐不住里按了不算，手柄上不出道具键。
- 速冻：原地冻 4 秒（`CFG.freezeTime`），冷却 12 秒（从用的那一下算）。身体换成运动学刚体钉住，碰撞体多一个 `FROZEN` 组：
  别人的身体碰得到它（能站上去），别人的手抓得住它，抓着它的人拉力照算（和站在地上一样实在）。冻着的人自己的手不动。
- 拉面：一只手抓着不动的地形（关卡的台子、墙；不是动台、跷跷板、绳子、队友）时才用得成，没抓着就报一次没用成（`item` 事件 `ok: false`），不进冷却。
  从抓点旁边的墙外垂下一根 10 × 20 px 的面条（会碰地形，顺着墙垂），能抓能爬，10 秒后断（抓着的手松开），冷却 15 秒。
- 荷叶：撑 5 秒，冷却 12 秒；悬空没抓东西时往下掉最快 150 px/s，摇杆推着横着飘（最快 260 px/s）。
- 新事件：`item`（谁、哪样、`ok`、在哪）、`itemEnd`（速冻化开、荷叶收起、拉面断了，在哪）。
- 手机局的快照：每个人那一行后面多两个数（正在起作用的道具、还剩几秒），拉面放在 `nd`（谁放的、还剩几秒、各点）。
- 没人用道具时物理和以前一模一样：24 关的回放照旧全过（`npm run levels`）。

## 帮手契约（A9c，11-13 Steve 定的「卡太久来帮手」）

- 闯关、大团队里有外卖无人机（主机开局时 `Rules.helper: true`；回放、验收、测试默认没有，回放不变）。一段（两个检查点之间）卡了 `CFG.helpAfter` 60 秒、全队摔了 `helpDeaths` 3 次以上，或者卡了 `helpLate` 120 秒，就飞来一架，悬在离下一个检查点（没有了就是终点）最远的那个人头上 `droneHang` 120 px。过一个检查点、无人机走了都重新数。
- 提手（外卖袋底下一根横杆，56 × 10）是运动学刚体上的一小条，能抓、跟着走，不碰人也不碰地形。等 `droneWait` 20 秒没人抓就飞走；有人抓住就先升到这一路最高的台子上面 200 px（至少比目标高），横着飞到下一个检查点上头，降下来悬 `droneDrop` 3 秒（或者没人抓着了）再飞走，飞出关卡顶上时还抓着的手松开。每秒 `droneSpeed` 170 px，几个人一起挂着也行。
- 事件 `drone`（`arrive` 飞来、`carry` 开始带人、`leave` 飞走），有叮咚和嗡嗡声，电视和手机局的手机上出横幅「外卖到了！抓住袋子底下的横杆」。手机局快照多 `dr`（提手在哪、在干什么，位置跟着匀）。抓着无人机的人背景音乐不算危险。
- 开发页 `play.html?helper=1&helpLate=5` 打开帮手、等 5 秒就来。

## 抢金元宝契约（A9d，11-13 第三轮的对战玩法）

- 多人里的一个玩法（`Rules.mode: 'gold'`），至少 2 个人。场地是 `goldArenas()`（`src/physics/arenas.ts`）：`gold-01` 元宝席（年夜饭桌：中间一张瓷台放元宝，两边各一块木台，上面几根横杆，底下一整片红油锅）、`gold-02` 金元宝浮台（温哥华：中间铁台放元宝，两边铁台，上面一块来回走的浮台）。场地多两样：`ingot`（元宝放在哪）和 `spawns`（每个人站哪，左右两边交替）。
- 元宝是一个 46 × 26、0.6 kg 的物体（`Prop.kind: 'ingot'`），能抓能拽能抢。只有一个人的手抓着时他攒时间（`CFG.goldHold` 5 秒赢一局）；两个人以上同时抓着谁都不算。攒的时间这一局里不清零，松手再抢回来接着攒。
- 元宝掉出场地（摔死线下面、碰到要命的东西）`CFG.ingotBack` 1 秒后回到中间，抓着它的手松开。摔了在自己那边复活，没有召唤，没有道具、帮手。
- 一场打到有人赢 `CFG.goldRounds` 5 局：主机赢一局时出横幅「×× 拿下第 N 局」和比分，2 秒后换下一张场地（两张轮着来，从大厅选的那张开始，曲子跟着换）接着下一局（房间一直在玩，不再倒数）；有人赢够了出结算页，`Results.rounds` 是每个人赢了几局，按局数排。
- 事件 `gold`（谁抓着、攒到第几秒，每攒一秒一次；`player: -1` 是元宝回到中间）。声音：抓上叮一声、每秒滴答越来越高、元宝回去呼的一声。画面：元宝金色，抓着的人头上一圈进度。背景音乐的催跟着最多的那个人攒了几成走。
- 比分（电视右上角，手机局每部手机的顶上，`results.ts` 的 `renderGoldScore`）：第几局，每人一个颜色点、名字（长的截短）、赢了几局；超过 4 个人只写颜色点和局数，横着的小手机也放得下。场地只有一屏，换场地时镜头直接看全场，不从边上摇过来。
- 手机局：快照多 `gd`（要攒几秒、谁抓着、每人攒了多少），手机上画同样的进度圈；`Cast.gold` 是这一场打到第几局、每人赢了几局，手机上写比分，新的一局出「第 N 局」。
- 开发页 `play.html?level=gold-01&mode=gold&players=2` 试玩。

## 小目标和红包契约（A9b，11-13 Steve 定的「每关小目标和红包」）

- 闯关和大团队每关三个小目标，各一颗星（`src/goals.ts`）：准时（par 的 1.5 倍以内到顶，取整到 10 秒）、少摔（全队摔的次数不超过 `par.deathsPerPlayer` × 人数）、红包（这一局把关里的红包都拿到；没红包的关没有这一颗）。坐不住、比谁先没有。
- 红包是关卡 JSON 的 `envelopes`（每关 3 个点，`npm run envelopes` 从四人回放里挑：有人的手够到过、站在路上拿不到的地方）。身体或手碰到（`CFG.envelopeR` 14 px）就拿到，事件 `envelope`（谁、第几个、在哪）。只是个点，不是碰撞体，物理和回放不变；`npm run levels` 查每关 3 个、在关里、不碰台子、回放里每个都有人拿到过。
- 主机到顶那一下算好，记在这台设备上（`src/host/progress.ts`，localStorage `hang-on:progress`：每关拿到过哪几颗星、拿到过哪几个红包；同一个红包再拿不算）。倒数时写三个小目标，玩的时候右上角是这一局拿了几个红包，结算页一颗颗打星（第一次拿到的带「新的星」）、写红包总数，大厅关名后面是拿到过的星，下面是一共攒了几个。
- 结算 `Results` 多 `goals`、`envelopes`（这一局拿到几个、一共几个、新拿到几个、一共攒了几个），手柄当遥控的结算和手机局的结算照样画；`Menu.level.stars` 是大厅那一关的星（「★★☆」）。手机局快照多 `en`（拿到的红包，按位）。

`fading`（饼干平台）：`{ x, y, w, h, material?, on?, off?, phase? }`，在 `on` 秒、消失 `off` 秒（默认 3 / 2），`phase` 把这块的钟往后拨几秒；消失时抓着它的手一起松开。
`springs`（弹簧蜡烛）：`{ x, y, w, h, power? }`，身体落在顶上就弹，`power` 1 约弹 250 px（5 个身高）；侧面能抓。

每关必须附一个回放脚本（`replays/<id>.json`，每帧 4 人的 `PadInput`），`npm run levels` 用它无头跑通整关，用时在 `par.seconds` 的 0.5 到 2 倍之间才算合格。

关卡按 id 末尾的号排（table-01 … van-12，再 table-13 … van-24），彩蛋关最后。

### 机关（A6）

- `hazards`（碰到就死）：`{ x, y, w, h, kind?, dir?, players? }`。`kind` 是 `spike`（尖刺，默认）、`hot`（烫）、`zap`（电），`dir` 是尖朝哪边（默认 `up`）。身体、手、胳膊肘碰到都算。它不是碰撞体，不能站也不能抓，下面要垫台子。样子按世界画：桌上是竹签、红油锅、电热丝，温哥华是铁栅栏、夜市烤架、黄黑电轨；三种死法各有特效和声音，摔下去还是原来的水花。
- `movers`（会动的台子）：`{ x, y, w, h, path, speed, wait?, loop?, phase?, material?, deadly?, hazard?, players? }`。(x, y) 是起点，沿 `path` 的点来回走（`loop: true` 绕圈），`speed` 每秒多少像素（最多 600），每到一个点停 `wait` 秒，起步和停下都是慢慢的；站在上面、抓着它都跟着走。`deadly: true` 是碰到就死的块（`hazard` 定样子，默认电），不能抓。走到头停下的地方不能插进别的台子。
- `spinners`（会转的杆子）：`{ pivot, arms, len, h?, spin, phase?, material?, deadly?, players? }`。绕 `pivot` 转，`arms` 根（1 到 6）均匀分开，每根长 `len`（40 到 400）、粗 `h`（默认 16），`spin` 每秒转几弧度（正负 4 以内，正数顺时针）。能抓能站；`deadly: true` 的带刺，碰到就死。
- `players: [min, max]`（按人数摆）：`rects`、`ropes`、`seesaws`、`crates`、`fading`、`springs`、`hazards`、`movers`、`spinners`、`plates`、`gates` 里的每一件都可以写，只在 min 到 max 个人时摆出来，比如人少时多一块台子、人多时缝更宽。开局按人数摆，半路进人不重摆（下一局再摆），手机局的快照带 `np` 告诉手机按几个人摆。
- 会动的东西的位置只由关卡数据和时间算（`src/physics/motion.ts`），物理和画面用同一套，快照里不带它们。
- 复活的地方（起点，每个检查点，四个人错开站）离要命的东西至少 84 px。
- 机关样板关：开发页 `play.html?level=proto-02`（桌上）、`proto-03`（温哥华），不进大厅。

### 踩板门（11-13，多人非配合不可的关用）

- `plates`（踏板）：`{ x, y, w, h, opens, material?, players? }`。地上一块矮按钮（高 8 到 20、宽 48 到 200），本身是实的（能站），底下要垫着台子。有人压着（身体贴着踏板上沿 `CFG.plateReach` 8 px 以内；冻住的人、箱子也算）就按下去。`opens` 是开哪几扇门（门的 id，几扇用空格分开）。
- `gates`（门）：`{ id, x, y, w, h, move, speed?, hold?, all?, material?, grab?, players? }`。一块运动学的墙或台子，能站能抓（`grab: false` 不能抓），站在上面、抓着它都跟着走。连着它的踏板按下时往 `move` 那边挪开（每秒 `speed` 像素，默认 260），没人按了还开着 `hold` 秒（默认 0.4）再挪回来；关的时候它要去的地方有人的身子就停住等，不夹人（站在门顶上也算挡着）。`all: true` 要连着的几块踏板都按着才开。门往上挪就是升降台。
- 事件：`plate`（第几块、按下还是弹起、在哪）、`gate`（第几扇、开始开还是开始关、在哪），有各自的声音。踏板和它开的门画成同一个颜色（第几扇门一个色），门上三道色条和一个锁。
- 手机局的快照多 `pl`（按着的踏板，按位）和 `gt`（每扇门开到几成，跟着匀），别的手机上的门和主机在同一个地方。
- 验收器：踏板开的门都有、每扇门都有踏板、踏板垫着台子、门开着关着都在关里、按人数摆时踏板和它的门同时在；每份回放里每扇门都真开过（全开）。
- 样板关：开发页 `play.html?level=proto-04&players=2`（一扇两边都有踏板的门；一面抓不住的高墙边的升降台），不进大厅。

### 难关（C8）

- id 是 `table-13` … `table-18` 和 `van-19` … `van-24`，可以分批交；在的每一关都要过下面全部规则。
- `teaches` 是 `spike`、`hot`、`zap`、`mover`、`spinner`、`gauntlet` 之一，大厅里显示「难关：…」。每个世界最后一关（table-18、van-24）是 `gauntlet`，至少用四种机关。
- 大小、出生点、终点、检查点（每屏一个、15 到 60 秒一段、四个人都有落脚）和前 12 关一样；高过一屏的按攀爬关查（高 1400 到 2200，至少往上一屏）。
- `par.seconds` 60 到 240，`par.deathsPerPlayer` 2 到 8。
- 难在哪：要命的东西至少 4 处，每一屏（攀爬关每一层）都有；至少一个会动的台子或会转的杆子。回放里每个不要命的机关都真的用上（站上去或抓着至少 0.25 秒），每处要命的东西都在路上（有人到过 240 px 以内）。这关得靠大家：回放里至少两段（两个检查点之间算一段）都有人连成串挂着（至少 0.25 秒）或者把队友丢过去，不能只在开头连一下；录好的每个手柄单独跑都过不去。
- 每关是自己的关：把台子（含饼干、蜡烛）的上沿按 40 px 一格比，和别的任何一关（现有 12 关、别的难关）重合不超过 60%（现有 12 关之间最多 55%）；出生点附近那一屏和别的难关重合不超过 85%。不能把一关换个名字、换个材质搬到另一个世界，也不能每关都用同一个开头。
- 12 关到齐以后的搭配：能站能抓的动台至少 3 关，能抓的转杆至少 3 关，要命的动块至少 2 关，要命的转杆至少 2 关，尖刺、烫、电各至少 3 关，按人数变的至少 4 关，每个世界至少一道攀爬。
- 按人数变的关：1 到 4 个人里每一种摆法都要一份回放。4 个人那种是 `replays/<id>.json`，别的是 `replays/<id>.p<人数>.json`（这份回放就是那么多人）。`players` 范围要从 4 或更少开始：闯关的关卡验到 4 个人（第 5、6 个人复活时站不住会自己往旁边挪），只给 5、6 个人的东西放到大团队的大关里（C9）。

### 大关（C9）

- id 是 `team-01` … `team-06`（1 到 3 年夜饭桌，4 到 6 温哥华），放在 `levels/team/`，给 4 到 6 个人。`teaches` 是 `longchain`（三个人以上连成一串）、`counterweight`（几个人一起压住、推动）、`relay`（把人丢过去、递上去）、`combine`（前面几样连着来）之一，每个世界最后一关（team-03、team-06）是 `combine`。
- 大小、出生点、终点、检查点和闯关一样，6 个人都要有落脚：出生点 `spawn.x + 44 × 人`、每个检查点 `cp.x + 30 × 人`（人 = 0 到 5）脚下 80 px 内有不会塌的台子。`par.seconds` 60 到 240，`par.deathsPerPlayer` 1 到 6。4、5、6 个人各一份回放 `replays/<id>.p<人数>.json`。
- **一两个人过不去**（11-13 第一版审出来加的）：一段是出生点到第一个检查点、一个检查点到下一个、最后一个检查点到终点。每关至少两段、而且不能只有第一段，是 1 个人、2 个人都过不去的。`npm run probe`（`scripts/probe.mjs`）查：从这一段的起点出发，1 个人乱按 200 次、2 个人乱按 100 次，每次 60 秒（摔了在这段起点复活），一次都到不了下一个检查点。4、5、6 个人的每种摆法都要过不去。CI 跑 `--quick`（60 次、30 次），交之前跑完整的。
- 要知道一个人能干什么：任何墙一个人都爬得上去（抓着墙面往上倒手）；一个人乱按能抓到平地上方 250 px 的横杆，能扑过 400 px 宽、下面是死的坑（扑到对面墙上再爬上去）；跷跷板是自由转的，一个人就压得翘。两个人乱按能翻过 300 px 高、墙面带电的墙。墙面贴着要命的东西（爬不了）、高 400 px 的墙，1 个人、2 个人乱按都过不去。
- **这几段真的靠大家**：回放在这一段里有 3 个人以上连成串挂着至少 0.25 秒（每个人都悬空，一个抓着一个，最上面的抓着地形或绳子）、3 个人以上一起站着或抓着跷跷板或箱子把它压翘、推走，或者把队友丢过去、递上去（松手时队友往右上飞，vx > 150、vy < −100）。每关至少有一段是 3 个人以上的串或者 3 个人以上一起压、推。
- **六关各是各的**：至少一关 `longchain`（回放里 3 个人以上的串至少 0.25 秒），至少一关 `relay`（丢人、递人至少两次）；`combine` 那两关的两段要大家的地方用的是两种不同的办法。不能六关都是同一个套路（比如都是「起台、跷跷板、一溜台阶」）。台子上沿按 40 px 一格比，和别的任何一关（现有 12 关、难关、别的大关）重合不超过 60%，出生点附近那一屏和别的大关重合不超过 85%。
- **人多变难，变在要大家的段里**：至少 3 关用 `players` 范围，变的东西在 1、2 个人过不去的那几段里（5、6 个人时坑更宽、抓点更高、少一个把手），不是把别处的一条缝变宽。
- **回放是真玩的**：所有人一起不动（摇杆不推、不抓）不超过 3 秒；每段 15 到 60 秒是玩出来的，不是等出来的。

### 后厨（A10，C10 做关）

- 世界 `"world": "kitchen"`（中餐馆后厨）：台子没写材质是不锈钢（`metal`），细木条画成砧板；要命的东西是插在刀架上的一排刀（`spike`）、坐在火上的炒锅（`hot`）、灭蚊灯（`zap`）；检查点是出菜口的保温灯；掉下去是一池洗碗水。背景音乐「中餐馆后厨」（难关是小调版）。材质多一个 `bamboo`（竹蒸笼）。
- `vents`（蒸笼喷汽）：`{ x, y, w, h, reach?, on?, off?, phase?, power?, material?, players?, until? }`。矩形是一摞蒸笼（实的，能站能抓，下沿垫在台子上，宽 48 到 200、高 24 到 120）。喷的时候蒸笼顶往上 `reach`（默认 300，120 到 480）像素、和蒸笼一样宽的汽柱里，人（身体和胳膊）、箱子、托盘被往上托：往上的速度没到 `CFG.ventLift`（620 px/s × `power`，0.5 到 1.6）就加，汽柱最上面 35% 越往上越弱。站在蒸笼上等它喷，人被托起约 360 px（比汽柱顶再高一点），这时候抓旁边的台子。`on` 喷几秒、`off` 停几秒（默认 1.4 / 2.2），喷之前 0.6 秒盖子跳、漏几缕汽；`phase` 把钟往后拨。钟在 `motion.ts` 的 `ventState`（物理和画面同一个钟，快照不带）。事件 `vent`（`warn` 快喷了、`on` 喷了），离大家远的那几摞不出声。汽柱下面六成不能有台子挡着。
- `tray`（端托盘）：几个点（托盘的中心，比台面高 5 px）：第一个是开局放哪，第 j + 1 个是托盘过了第 j 个检查点以后翻了回哪。闯关、大团队里关卡有这一项就摆一个托盘（92 × 10，0.15 kg，底下滑），上面三样点心。**托盘也端进终点才过关**：人都到了、托盘没到不算（主机每 5 秒提醒一次「点心还没端到」）。一只手抓托盘中间端得平（拖着走、吊着都平）；抓一头就往下歪。歪过 0.7 弧度超过 0.3 秒、掉到摔死线下面、碰到要命的东西，点心就翻了（事件 `tray` 的 `spill`），1.2 秒后托盘摆平回到存档的地方（`back`），回来后 1 秒里不算翻。托盘离大家激活过的检查点 160 px 以内就存档到那个检查点。托盘进了终点（四边各放宽 20 px）报 `home`。镜头也框着托盘（落在后面了就拉远）。比谁先、坐不住、抢金元宝里没有托盘。手机局快照多 `ty`（托盘是第几个物件、翻没翻），物件的种类码 3 是托盘。
- 悬在空中的物件不算实在（A10 改的，见 `docs/physics-notes.md`）：抓着箱子、托盘、元宝往上推，物件得贴着地形或别的物件才算连到实在的地方；悬在空中的物件和悬空的队友一样，只有 `CFG.airPullTime` 那一秒的余量。不然端着托盘往上推能把自己推上天。24 关的回放不变。
- 样板关：开发页 `play.html?level=proto-05`（两摞蒸笼、热锅、灭蚊灯、刀、托盘），不进大厅。
- C10 的六关：`levels/kitchen-25.json` … `kitchen-30.json`，写 `"tier"`（25、26 简单，27、28 中等，29、30 困难），困难那一档按难关的规矩查（要命的东西、每屏都有、动台或转杆、两段靠大家、单个手柄跑不过）。`teaches` 是 `steam`、`tray`、`combine`，困难那一档也可以是难关那几样。至少 4 关有蒸笼、3 关有托盘、2 关两样都有；刀、炒锅、灭蚊灯各至少 2 关。回放里每摞蒸笼都真把人托上去过（0.25 秒），托盘端进了终点。简单、中等的关另要一份 1 个人的回放（`replays/<id>.p1.json`）：单人模式也玩这些关。别的照闯关（大小、检查点、每段 15 到 60 秒、3 个红包、和别的关重合不超过 60%）。

### 雪山（A10，C11 做关）

- 世界 `"world": "snow"`（雪山缆车）：黄昏的雪峰、半山的松树和缆车塔架、亮灯的木屋，一直下雪；台子没写材质是木头，所有台子顶上积一层雪；材质多一个 `snow`（压实的雪，摩擦 0.7）。要命的东西是冰锥（`spike`）、篝火（`hot`）、漏电的电轨（`zap`，和温哥华一样黄黑）；检查点是木屋的马灯；掉下去是雪坑（噗的一声）。背景音乐「雪山缆车」（古筝、卡林巴、沙锤，轻轻摇摆；难关是小调版）。
- `lifts`（缆车）：`{ from, to, speed, gap, drop?, kind?, phase?, players? }`。一根缆绳从 `from` 到 `to`（两头是站，画成大轮子），一串椅子沿着缆绳从 from 往 to 走（`speed` 20 到 240 px/s），每隔 `gap`（150 到 800）一把，走到 to 那头收进站里（站在上面的掉下来、抓着的手松开），过一会儿从 from 那头再出来。座板吊在缆绳下面 `drop`（默认 70，40 到 200）。`kind`：`chair` 缆椅（默认：72 宽的座板能站，上面 56 宽的横杆能抓）、`cabin` 缆车厢（120 宽的地板能站，上面一块顶能站能抓）。位置只由关卡和时间算（`motion.ts` 的 `liftChairs`、`liftParts`，快照不带）。缆绳至少 300 px 长；椅子一路上不能撞台子（验收器沿缆绳每 20 px 量一次）。到站前要有台子接着下车的人。
- `slip`（冰溜子）：台子（`rects`）的一项，一只手抓着它最多 `slip` 秒（0.6 到 5）就滑脱，滑了 `CFG.slipCooldown` 秒抓不了；快到时（最后 `CFG.slipWarn` 1.5 秒）手抖、圈变红（电视和手机局都有，快照多 `ic`）。画成一层亮晶晶的冰壳。站在上面不滑（要站不稳用 `ice` 材质）。坐不住的手滑和它一起算，哪个先到算哪个。
- 样板关：开发页 `play.html?level=proto-06`（一条缆椅、一节缆车厢、一面冰墙、冰锥、篝火、电轨），不进大厅。
- C11 的六关：`levels/snow-31.json` … `snow-36.json`，规矩和后厨一样（写 `"tier"`，31、32 简单，33、34 中等，35、36 困难；困难那一档按难关的规矩查；简单、中等另要 1 个人的回放；每关自己的布局；冰锥、篝火、电轨各至少 2 关）。`teaches` 是 `lift`、`slip`、`combine`，困难那一档也可以是难关那几样。至少 4 关有缆车、3 关有冰溜子、2 关两样都有。回放里每根缆绳都有人坐过（站在座板上或抓着椅子 1 秒），每块冰溜子都有人抓过。缆车的椅子算在会动的东西的预算里（每把一件）。

### 老宅（A10，C12 做关）

- 世界 `"world": "house"`（老宅找钥匙）：月夜的老宅，一轮大月亮，远处白墙黛瓦的马头墙，院子里老梅树、月亮门、透着暖光的窗棂，近处红漆柱子和挂落，萤火虫飘；台子没写材质是木头（顶下一道红漆），材质多一个 `brick`（青砖，摩擦 0.7，顶上一道黛瓦）。要命的东西是一地碎瓷片（`spike`）、铜炭盆（`hot`）、漏电的老电线（`zap`）；检查点是灯台上的油灯；掉下去是院子里的荷花池。背景音乐「老宅找钥匙」（A 羽调五声，马林巴、卡林巴像八音盒、笙，木鱼像老钟在走，一点摇摆；难关是 C 羽调的急版）。
- `keys`（钥匙）：`{ x, y, opens, players? }`，(x, y) 是钥匙的中心（38 × 14，比台面高 7 px，放在一直在的台子上）。`opens` 是一扇门（`gates` 里的 `id`）：钥匙开的门不连踏板，一扇门最多一把钥匙。钥匙是物件（0.1 kg，能抓、能拽、能丢，一只手拿着走、挂着都不碍事）；碰到它的门（离门不到 `CFG.keyReach` 26 px）门就开了、一直开着（门照 `move` 挪开），钥匙插在锁里没了（抓着的手松开）。门关着的时候长的那一头两边都要贴着台子（或关卡边），真挡路；门画成钉铜钉的木门，中间挂一把铜锁。钥匙掉下去、碰到要命的东西，1 秒后回来：回到它到过的最后一个大家激活过的检查点（离检查点 160 px 以内就算到过，放在复活的人头顶上），没到过就回开局的地方。事件 `key`：`found`（头一回有人抓住）、`unlock`（开了门，x、y 是门的中间）、`back`（掉了回来）、`locked`（有人走到锁着的门跟前，隔 5 秒报一次，电视和手机上提醒「门锁着，先找钥匙」）。每种玩法都有钥匙（比谁先里谁开了门大家都能过）。
- `lanterns`（手提的灯笼）：`{ x, y, players? }`，(x, y) 是灯笼的中心（30 × 40，比台面高 20 px）。物件，拿着走照亮周围 300 px，碰到灭着的灯就点着它；掉了和钥匙一样回来。一关最多 2 个。
- `lamps`（墙上的灯）：`{ x, y, r?, off?, players? }`，(x, y) 是火苗。亮着照亮周围 `r`（默认 260，120 到 480）。`off`：一开始灭着（只有一根灯芯，黑里有一小点光，看得出能点），有人的身体、手或者灯笼碰到（`CFG.lampTouch` 36 px）就点着，点着了一直亮（事件 `lamp`）。不碰撞、不挡路。一关最多 24 盏。
- `dark`（黑屋子）：几个矩形（最多 8 个，在关里）。里面看不清，只有光照得到的地方看得见：每个人身上一圈（170 px）、亮着的墙灯、灯笼、亮了的检查点（没亮的一小点）、没用掉的钥匙一闪一闪、要命的东西自己发光（炭盆、电线；碎瓷片反一点光）、终点。只管画面，物理照常。每间黑屋子里至少有一盏墙灯，或者关里有灯笼。黑屋子连地板一起框进去（不然地板是亮的）。画法：一张屏幕 1/3 大的光照图乘在世界上（`src/render/dark.ts`），没有 WebGL 的时候整块压暗一半。
- 手机局快照多 `ky`（每把钥匙是第几个物件、找到没有、用掉没有）和 `lm`（亮着的墙灯，按位）；物件的种类码 4 是钥匙、5 是灯笼。
- 样板关：开发页 `play.html?level=proto-07`（院子、黑库房、灯笼、灭着的蜡烛、柜顶的钥匙、锁着的门、炭盆、老电线），不进大厅。
- C12 的六关：`levels/house-37.json` … `house-42.json`，规矩和后厨、雪山一样（写 `"tier"`，37、38 简单，39、40 中等，41、42 困难；困难那一档按难关的规矩查；简单、中等另要 1 个人的回放；每关自己的布局；碎瓷片、炭盆、老电线各至少 2 关）。`teaches` 是 `key`、`dark`、`combine`，困难那一档也可以是难关那几样。至少 4 关有钥匙、3 关有黑屋子、2 关两样都有、2 关有灯笼、2 关有要点的灯。回放里每把钥匙都开了它的门（每份回放），主回放里每盏灭着的灯都点着了。钥匙和灯笼算在会动的东西的预算里（每个一件）。

### 太空站（A10，C13 做关）

- 世界 `"world": "space"`（太空站）：深空，满天星、紫蓝的星云、一颗带光环的大行星；远处空间站的桁架和太阳能板，中间一节节舱段（圆舷窗亮着），近处的钢梁；偶尔一颗流星。台子没写材质是白舱壁（`hull`，摩擦 0.5，一块块方面板，顶上一道青色灯带）；`peg` 画成金属扶手。要命的东西是撕开的铝板碎片（`spike`）、推进器的喷口（`hot`，喷蓝白的火）、激光栅栏（`zap`，两头发射器，中间一道红光）；检查点是信标灯；掉下去是飘出舱外（一声长长的呼）。背景音乐「太空站」（C 宫调五声，古筝像竖琴、卡林巴像星星、暖的合成器铺得很宽，不摇摆；难关是 D 羽调的急版）。
- `zerog`（失重区）：几个矩形（最多 6 块，每块至少 200 × 200，可以框到摔死线）。身体中心在里面的人，身体和胳膊都不受重力，飘着；物件（跷跷板除外）也飘。没抓东西时摇杆往那边轻轻喷气（每秒加 `CFG.floatThrust` 260 px/s，喷到 `CFG.floatMax` 170 px/s 就不再加；推墙、拽着队友甩出去可以更快），阻尼 `CFG.floatDamp` 0.35，慢慢停下来。伸手的力在失重区里反过来加在身体上（光挥胳膊不会飘走），胳膊的阻尼调小（`CFG.floatArmDamp`）。抓着扶手、墙照常拉。飘出失重区重力马上回来：失重区底下没有地板就会掉下去。事件 `float`（谁飘进、飘出）。失重区画成一块淡淡的光场，虚线框，里面浮着小光点。
- `levers`（拉杆）：`{ x, y, opens, w?, h?, players? }`，(x, y) 是把手的中心（默认 44 × 14，一块能抓的小地形，`level.ts` 的 `leverRect`）。有活着的人的手抓着就算拉下去（事件 `lever`），开 `opens` 那几扇门（`gates` 的 id，空格分开），和踏板一样：门写 `all` 就要连着它的拉杆、踏板都按着才开；松手过门的 `hold` 秒再关。一扇 `all` 的门的几根拉杆两两隔开 300 px 以上（一个人两只手够不着两根，得几个人一起拉）。一根拉杆开的门、`hold` 长一点（比如 3 秒），一个人拉一下松手跑过去也来得及。拉杆的底座和它开的门同一个颜色，拉下去把手往下扳、灯变绿。手机局快照多 `lr`（拉着的拉杆，按位）。
- 样板关：开发页 `play.html?level=proto-08&players=2`（一段失重舱、几根扶手、一道激光栅栏，两根隔得老远的拉杆开一扇舱门），不进大厅。
- C13 的六关：`levels/space-43.json` … `space-48.json`，规矩和后厨、雪山、老宅一样（写 `"tier"`，43、44 简单，45、46 中等，47、48 困难；困难那一档按难关的规矩查；简单、中等另要 1 个人的回放；每关自己的布局；碎片、喷口、激光各至少 2 关）。`teaches` 是 `float`、`lever`、`combine`，困难那一档也可以是难关那几样。至少 4 关有失重区、3 关有拉杆、2 关两样都有、2 关有几根拉杆一起开的门（`all`）。回放里每块失重区都有人飘过 1 秒、每根拉杆都有人拉过（每份回放）。简单、中等要一个人过得去：别用几根拉杆一起开的门。

## 音乐契约（11-13 Steve：「每个不同的场景需要有不同的背景音乐，并且会根据玩家的游戏状态比如是否处于危机时刻及时调整音乐的节奏」）

- 每个场景一首（`src/audio/themes.ts`）：年夜饭桌（D 宫调五声，古筝、琵琶、笙、木鱼、大鼓、板、小镲、锣）、温哥华海湾（E 大调五声，马林巴、卡林巴、暖的合成器、沙锤、边击、底鼓，轻轻摇摆）、中餐馆后厨（A10，G 宫调五声，马林巴领、琵琶、笙，木鱼一串串像切菜，不摇摆）、雪山缆车（A10，A 宫调五声，古筝领、卡林巴、暖的合成器、沙锤，轻轻摇摆）、老宅找钥匙（A10，A 羽调五声，马林巴领、卡林巴像八音盒、笙，木鱼像老钟，和弦里一个 E 大三听着有点悬，一点摇摆）、太空站（A10，C 宫调五声，古筝像竖琴、卡林巴、暖的合成器铺得很宽，鼓很轻，不摇摆）；困难（13 号往后）和坐不住放同一个场景的小调版（更暗、更快、鼓更多）。旋律、和弦、节奏型都是自己写的。每关的种子（关的 id）换段落顺序、调高或调低两个半音，同一个场景每关听着不一样。新场景做好时在 `THEMES` 加一首、`themeFor` 接上；没写的场景先放年夜饭桌。
- 全部现场合成（`src/audio/music.ts`），没有音频文件：拨弦是卡普拉斯-斯特朗（加全通补小数，高音也准），马林巴、卡林巴、圆低音是几个泛音各自衰减，鼓是扫频的正弦加滤过的噪声，铺底是振荡器；第一次用到一个音时算一次存着。混响是程序算的冲激响应。
- 紧张（0–1，`src/audio/tension.ts`）：每个人的危险看脚下多空（脚下 120 px 以内有台子不算，620 px 以上最高）、几只手抓着（两只手 0.35、一只手 0.7、没抓 1）、在不在往下掉（往下快过 450 px/s）、离尖刺热锅电线这些多近（110 px 以内）；冻住的人算安全，撑荷叶的减半。最危险的人七成、大家平均三成。再加「催」：最后一段、离终点 700 px 以内、比谁先有人到了、坐不住剩两三个人、准时那颗星用了四分之三以后。紧张 = 0.3 + 0.62 × 危险 + 0.3 × 催，变紧张约 0.35 秒跟上，放松约 2.5 秒；摔死、出局往上顶 0.3，背叛 0.2，过检查点松 0.2。用 24 关的四人回放量过：简单关几乎不到危机，难关危机占一到三成。
- 紧张 → 音乐（`src/audio/composer.ts`）：0.1 左右只有铺底和慢琶音；0.3 到 0.45 加低音和旋律；0.55 以上整套鼓，速度从这里往上提，到 1 是这首最快的速度；0.75 以上是危机：鼓变密、加镲和通鼓，低音变急，琵琶轮指，旋律叠高八度。每 40 ms 往后排 0.18 秒的音，速度和各层响度每一格按当时的紧张算，变化不超过一拍就听得出。
- 阶段：大厅、结算轻轻放（紧张 0.06，一半音量）；倒数从头起；到顶在下一拍弹主和弦、敲一下锣（镲）收掉；有人摔死、出局音乐让一下（叫声听得清）；过检查点旋律往上走三个音。
- 只在开房那台设备上放（电视局是电视，手机局是房主的手机），和音效同一个 AudioContext，接在音效的总音量上，静音键一起管。浏览器要点过一次页面才出声：电视那边没点过时，声音键写「点一下这页才有声音」。页面藏起来时停，回来从现在接着放。
- 试听页 `/hang-on/music.html`：选场景、拖紧张、点事件，有 40 秒演示；`hangOnMusic.renderWav(曲子, 秒, 'demo' 或紧张)` 用 OfflineAudioContext 离线导出 WAV（和游戏里同一套）。

## 玩法契约（A7，11-12 Steve 定的「开始之前可以选」）

大厅里开局前选，`Sim` 的第三个参数 `Rules { mode, teams? }`：

- `climb` 闯关：照旧，大家都到终点才算过，摔了回最近的检查点。1 到 6 个人。
- `team` 大团队：规则和闯关一样，关卡是 `levels/team/*.json` 里给 4 到 6 个人的大关（C9），至少 4 个人；还没有大关时大厅里不出这个键。
- `race` 比谁先：至少 2 个人。各跑各的：每个人有自己的检查点，进了终点就停在终点里（不动、不会死），只剩一个人没到、或者第一个到了以后 40 秒（`CFG.raceGrace`）就完，第一个到的赢；别人可以拽，召唤不能用。分两队（`teams`，按座位一个甜队一个咸队）：每队有自己的检查点，召唤只拉自己队的，哪一队的人先都到了那一队赢。
- `last` 坐不住：至少 2 个人，用场地（`src/physics/arenas.ts`，`level.arena`，没有终点和检查点）。摔了不复活（出局），平台按 `until` 一块块塌（提前 2 秒抖），一只手抓同一个地方 6 秒（`CFG.lastGripMax`）就滑，滑了 0.8 秒抓不了，最后还挂着的赢；最后几个同时掉下去算平局。
- `gold` 抢金元宝：至少 2 个人，用元宝场地，规则在「抢金元宝契约」。
- 新事件：`finish`（比谁先到了，第几个）、`out`（坐不住出局）、`crumble`（定时的东西塌了）、`slip`（手滑了）；`win` 带 `who`（赢的人），`checkpoint` 比谁先时带 `player`。
- 手柄的小包多了 `mode`、`team`、`place`、`out`；样子名单多了 `mode`、`teams`；结算的数多了 `mode`、`winners`、`teams`、`order`。快照里一个人「死了」那一格 2 表示比谁先到了终点。
- 定时塌的东西（`until`，几秒后塌，不再回来）：`rects`、`fading`、`springs`、`movers`、`spinners` 都可以写，关卡和场地都能用。

### 单人、多人和难度（11-13 Steve：「进去之后可选择单人模式和多人模式，然后选择简 中 难，多人模式的场景需要有团队配合才能通关」）

- 大厅先选单人还是多人（`src/sides.ts`）。单人只有闯关，只能一个人（两个人以上开不了，大厅说「单人只能一个人玩，人多就选多人」）；多人至少两个人，玩法是一起闯关（`climb`）、比谁先、坐不住、抢金元宝、大团队（大团队至少四个）。没人点过就跟着人数走：一个人是单人，进来第二个人自己变多人；有人点了单人多人或者多人里的玩法，就照点的。
- 闯关和比谁先再选难度（`Tier` 0 简单、1 中等、2 困难，`levels.ts` 的 `tierOfLevel`）：1 到 6 关和彩蛋关简单，7 到 12 关中等，13 号往后困难。关名在这一档里从 1 数。结算页的「下一关」打完一档接着下一档的第一关。坐不住、抢金元宝、大团队不分难度。
- 多人的一起闯关这一档有多人的关（`levels/multi/*.json`，写 `"tier"`，Codex 的 C14 做）就用多人的，还没有就用和单人一样的那一串。比谁先一直用单人那一串（一个人过得去的关）。
- 主机页 `?side=solo|multi`、`?tier=0|1|2` 直接开到那里，`?level=` 开到那关所在的难度。手柄当遥控多两条命令 `{ do: 'side' }`、`{ do: 'tier' }`；`Menu` 多 `side`、`tier`、`tiered`，倒数的关名前面写难度（「简单 · 2. 碗沿小缝」）。

### 新机关（A12，11-18 Steve：「机关太温和」，四个都要）

开发页 `play.html?level=proto-09&players=2` 是样板关（会塌的台阶、来回荡的铁锅、抓着荡过缝的锅、往回刮的风里抓小钉、爬墙时底下涨汤）。四样都可以用在任何世界，C16 的长关用。

- **涨潮** `Level.tide { speed, delay?, from?, top? }`：底下的汤 / 水从 `from`（不写是 `deathY`）开始，开局 `delay` 秒后每秒涨 `speed` 像素，涨到 `top`（不写是终点底下 40 像素）停。身子低过水面就死（`death` 的 `cause: 'tide'`，在水面上溅起来）。有人复活或被召唤回来时，水面离那里不到 `CFG.tideGap`（260）就退到那下面 `tideGap`，停 `CFG.tidePause`（2.5 秒）再涨。事件 `tide { phase: 'rise' | 'back', y }`；横幅按世界说汤、海水、冰水、池水、能量潮（中英两套）。物件掉进水里也算丢。快照 `td`。验收：`speed` 5–45、`delay` 2–40、`top` 在终点下面；每份回放里水面离最低的活人最近不到 400 像素（真追上来了）。
- **会塌的台子** `Rect.crumble`（秒）、`Rect.regrow`（秒，不写是 `CFG.crumbleRegrow` 6）：有人站上去或手抓着才开始倒数（报 `creak`），最后 `CFG.crumbleWarn` 秒抖，到点塌（报 `crumble`，站着的掉、抓着的松开），过 `regrow` 秒长回来（报 `regrow`；那时有人压在那儿就再等等）。台面画裂缝。复活点不选会塌的台子。快照 `cb`（0 没人碰、正数是哪一秒塌、-1 塌了）。验收：`crumble` 0.5–4、`regrow` 2–12、宽不过 400、不和 `until` 一起写；主回放里每块都有人碰塌过。
- **摆锤** `Level.pendulums[] { pivot, len, amp, period, phase?, r?, grab?, deadly?, players? }`：锤是运动学的圆（半径 `r`，不写 34），角度 `amp · sin(2π(t + phase)/period)`，最低点在轴心正下方 `len`。撞上按锤的速度把人推开（`CFG.pendulumKick` 倍，最多 `pendulumKickMax`，同一个人 `pendulumKickCd` 秒一次，报 `bonk`）；默认能抓（抓着跟着荡），`grab: false` 不能抓；`deadly` 是烧红的铁锅，碰到就死（`hot`）。锤按世界画（铁锅、浮标、雪球、灯笼、维修舱）。按时间算，手机局不用带。验收：`len` 80–600、`amp` 0.15–1.4、`period` 1.2–6、`r` 20–60、摆到两头都在关里；每份回放都有人从锤旁边过；算会动的东西（≤ 40）。
- **阵风** `Level.winds[] { x, y, w, h, dir, force?, on?, off?, phase? }`：矩形里一阵一阵往 `dir`（left / right / up / down）刮：先停 `off` 秒（不写 2.5，最后 `CFG.windWarn` 0.7 秒起风丝），再刮 `on` 秒（不写 1.5）。刮的时候矩形里的人（身子、胳膊）和物件的速度往风那边加（`CFG.windAccel` × `force`），最多 `windMax` × `force`。报 `wind { index, phase: 'warn' | 'on', x, y }`；画风丝，平时淡、快刮时多、刮时又密又亮。按时间算。验收：至少 160 × 160、`force` 0.5–2、`on` 0.6–4、`off` 0.8–6；每份回放都有人被刮过 0.5 秒。
- 声音：涨潮是一声低号加咕嘟，水退是哗；台子吱嘎加咔；长回来「啵」；摆锤撞人「哐」；风是「呼」。

### 长关（A13，11-18 Steve：「关太短太直」，选了「新做一批长关替换最短的」）

关的 JSON 写 `"long": true` 就是长关，大厅的「这关教」前面多一句「长关 · Long level」。替换最短的关：编号、世界、难度不变，名字、「这关教」、布局全换。只有新场景的关（`kitchen-` `snow-` `house-` `space-`）和多人关（`multi-`）能写；多人的长关也可以用四个新场景的世界。

验收器（`longLevel`）查：

- 路要绕、要长：检查点不用一直往右（按路上的顺序、隔开 120 像素以上），至少 5 个检查点（6 段，每段照旧 15–60 秒）；从出生点经过每个检查点到终点中心，连起来至少 6000 像素（现在的关 2000–4000）。尺寸照旧最多 3600 × 2200，所以只能绕：往右、爬上去、往回走、再爬
- 至少用两样新机关（涨潮、会塌的台子、摆锤、阵风）；简单的长关不涨潮、摆锤不烫
- 中等、困难：`stamina: true`（按手酸录），会动、会转、会荡的东西（movers + spinners + pendulums）至少 3 个；困难至少 6 个，其中至少 2 个快的（台子 ≥ 120 px/s、转杆 ≥ 1.5 rad/s、摆锤周期 ≤ 2.4 秒）
- par 150–360 秒，每人死的预算 0–10（困难 2–10，多人 1–10）；主回放（多人关每份回放）至少 150 秒
- 别的规矩照旧：每屏一个检查点、困难每屏有要命的东西、台子和别的关重合不超过 60%、红包、按人数摆、多人关一个人过不去的段（`C14_MULTI_SECTIONS`）、新场景自己的机关和搭配
- 最后一行 `long: N long levels (id 路长, …)`

多人关的新机关也照单人关查：涨潮追得上人、摆锤旁边有人过、阵风刮到过人（每份回放），每块会塌的台子至少一份回放里碰塌过。

### 手酸（A11，11-18 Steve：「抓得太稳」，选了「只在中等和困难加」）

- `Rules.stamina`：`'medium'` 或 `'hard'`，不写就没有手酸。主机在分难度的玩法里选了中等、困难，**而且这关写了 `"stamina": true`**（回放是按手酸录的、验收按手酸跑过）才给；简单、大团队、坐不住、抢金元宝都没有。
- 每个人有力气 `Player.stamina`（1 是满的）。身体没站在东西上、至少一只手抓着就往下掉：两只手 `staminaTwo*` 秒用完（中等 18、困难 11），一只手 `staminaOne*` 秒（中等 10、困难 6）；身上每多挂一个人（直接抓着他的，一个人两只手也算一个），累得快 `staminaLoad`（0.6）倍。站在东西上（或在失重区里飘着）`staminaRest*` 秒回满（中等 3、困难 4），悬空又没抓东西每秒回 `staminaAir`（0.08）。冻住（速冻）的人不算累。回检查点（`teleport`）力气是满的。
- 用完：两只手都松开，每只手报 `slip`，人报 `tired`，`staminaCooldown`（1 秒）抓不了。剩不到 `staminaWarn`（0.3）时抓着的手抖、圈变红、冒汗；没满的时候头顶右上角有一小圈力气（绿、黄、红）。`tired` 的声音是呼一大口气。
- 手机局快照每个人第 31 个数是力气（老主机不发就当满的）。
- 大厅「这关教」那一行、手柄菜单在中等、困难的手酸关后面带一句「挂久了手会酸，站一会儿就好 / Hands tire if you hang too long. Stand to rest」。
- 验收（`npm run levels`）：写了 `stamina: true` 的关开着手酸跑全部回放；简单的关不许写；最后多一行 `stamina: N/M` 报中等、困难里有几关已经按手酸录过。C15、C16、C17 合并以后（11-21）是 40/40，从此成了规矩：中等、困难的关（闯关和多人）没写 `stamina: true` 验收就不过，新做的中等、困难关都按手酸录。开发页 `play.html` 写了 `stamina: true` 的关自己开着，`?stamina=1` 不管写没写都按关的难度开（重录回放用），`?stamina=0` 关掉。
- 11-18 第一批（现有回放开着手酸也都过的）：van-07…12、kitchen-27/28、house-39…42、space-45…48、multi-04…09，一共 22 关；还差 table-13…18、van-19…24、kitchen-29/30、snow-33…36，要按手酸重录（Codex）。
