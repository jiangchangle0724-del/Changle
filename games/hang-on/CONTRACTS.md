# 抓紧了 · Hang On 契约

所有人（Claude Code、Codex、以后的你自己）都按这份来。改契约先改这个文件，再改代码。

## 两条铁律

1. **主机是唯一的真相。** 物理只在主机页跑一份。电视局的手柄页只发输入、只显示自己的状态，不渲染世界。手机局（下面「手机局契约」）里别的手机画的是主机发来的快照：只在收到的两张之间匀，不预测、不跑物理。两边不一致的 bug 在这个架构下不存在，别为了「流畅」把物理搬到手机上。
2. **仓库里不出现原版的名字。** 代码、文案、资产文件名、提交信息、注释里都不能有原版游戏名、工作室名、发行商名（三个词见 `docs/hang-on.md` 开头的法律线，禁词表只放在那里）。机制可以一样，角色、关卡、美术、名字全部原创。CI 的 `npm run ip-check` 对 `docs/` 之外全仓库 grep，为零才能合并。

## 手感契约（原型已验证，Rapier 版必须对齐）

| 项 | 原型值 | 允许范围 |
| --- | --- | --- |
| 胳膊长 | 6 节 × 15 px = 90 px | 身高（直径 48）的 1.6 到 2.2 倍 |
| 重力 | 1700 px/s² | 看下落 1 个身高用时 0.17 秒左右 |
| 抓取判定 | 手半径 10 + 7 px 容差 | 按下 1 帧内必须抓上，没有「滑手」 |
| 挂着时的操作 | 摇杆 = 身体想去的方向 | 不可改。往上推翻上去，左右推是荡 |
| 系绳 | 身体到抓点 ≤ 胳膊长 + 肩宽 + 2 | rope joint，不可省 |
| 荡的助力 | swingBoost 1100 | 按节奏推 3 下荡幅 ≥ 60 px |
| 摩擦 | 地面 0.85、墙 0.97、随压力缩放 | 能抓着墙爬，不能粘在墙上 |
| 复活 | 掉出 deathY 后 1 秒回最近检查点 | 不可改成全队重来 |

来源：`proto/physics.js` 的 `CFG`，`proto/sim.test.mjs` 的 20 条检查。Rapier 版把这 20 条移植过去，**允许调阈值，不允许删检查**。

## 输入契约（手柄 → 主机）

每帧一条，不可靠无序通道（`ordered:false, maxRetransmits:0`），只发最新状态，主机丢弃比已收到更旧的 `seq`。

```ts
type PadInput = {
  seq: number;        // 单调递增
  t: number;          // 手机 performance.now()，用来算往返
  ax: number;         // 摇杆 x，-1..1
  ay: number;         // 摇杆 y，-1..1（上为负）
  gl: boolean;        // 左手抓
  gr: boolean;        // 右手抓
  act?: 'summon' | 'emote';   // 偶发动作，可省。手柄连发十几帧保证送到，主机 1 秒内同一个动作只算一次
};
```

`summon`（A3）：摔死还没复活的队友立刻从按键的人身上掉出来。

主机 → 手柄只发小包，每 250 ms 一条：`{ color, hands:[bool,bool], deaths, rttMs, phase, direct, teamDead }`。

## 样子契约（A3）

手柄选的样子 `Look = { hat, glasses, eyes, face, arms, voice }`（可选项和中英名字在 `src/look.ts`），连上房间时和改了之后
经房间发给主机（`LinkMsg { k: 'look', look }`，走可靠的 WebSocket，不走数据通道），主机用 `cleanLook()` 收拾。
手套颜色不能换：左蓝右橙是辨左右用的，袖子也不许用蓝和橙；馅儿色跟座位走。`voice` 是摔下去时的尖叫，`auto` 按座位分四个音高。

## 语言契约（A3）

玩家看到的字中英都有。页面里写死的字用 `data-en`（`data-en-label` / `data-en-ph` / `data-en-title`）标英文，代码里用
`tr('中文', 'English')`（`src/i18n.ts`）。语言先看 `?lang=`，再看自己记的，再跟主站设置，最后看手机语言；主机和手柄各自切。

## 房间契约

沿用 party-base 的房间与阶段机：`lobby → countdown → playing → results → ended`。结算页可以直接 `START` 回到 `countdown`（「下一关」「再来一次」不绕回大厅），`LOBBY` 从倒数、玩、结算都能回大厅。房间码 4 位、最多 4 个手柄 + 任意观众、主机断开 30 秒房间作废。信令走 Durable Object（和一起跳同一个），直连失败 3 秒后自动走中转并在主机屏幕角落提示。

手机局的房间：开房时 `POST /hang-on/api/rooms` 带 `{"hostPlays":true}`。房主自己占一个人和 0 号颜色，手柄最多 3 个、颜色从 1 号起；`RoomView.hostPlays` 让每部手机知道这是手机局。

## 手机局契约（11-11 Steve 定的「不要电脑，每人手机上都有画面」）

- 在手机上打开主机页（触屏、屏幕短边不到 600）就是手机局；`?phone=1` 强开、`?phone=0` 强关，大厅里触屏设备有一个键在两种局之间换。
- 房主那部手机照样开房、跑物理、画画面，自己用压在画面上的摇杆和抓键玩（排在手柄后面）。
- 画面快照（`LinkMsg { k: 'snap', s: Snap }`，格式在 `src/net/protocol.ts`，压和拼在 `src/net/snap.ts`）：直连每 50 ms、绕路每 100 ms 给每部手机一张，四个人加机关压成文字不到 2.5 KB。直连走不可靠无序通道，丢了下一张补上。
- 手机收到快照就从「现在画着的样子」匀到新快照，一个快照间隔匀完（比主机晚约 50 ms）；人一下子挪得很远（复活、再来一次）就直接跳过去。匀和收快照用同一个钟（`performance.now()`）。
- 事件（抓、松、摔、过关……）跟着快照走：每件有编号，跟着 6 轮快照走完才拿掉（按轮数，不按时间：房主卡一下也丢不了），手机按编号只放一次。
- 样子名单（`LinkMsg { k: 'cast', c: Cast }`）：谁叫什么、什么颜色、什么样子，以及「你是第几个人」；变了就发、每 2 秒补一次，走房间（可靠）。到了结算页带着结算的数（`Results`），每部手机按自己的语言画结算页。
- 声音：每部手机只放跟自己那个人有关的和大家共有的（检查点、饼干、过关），几部手机放在一张桌上不会一下响四遍。
- 画面那部分（Pixi）进了手机局才下载，不带 Rapier；电视局的手柄不下载它。

## 关卡契约（Codex 做关时照这个）

```json
{
  "id": "table-03",
  "world": "table",
  "name": { "zh": "筷子桥", "en": "Chopstick Bridge" },
  "teaches": "swing",
  "spawn": { "x": 120, "y": 600 },
  "goal": { "x": 1560, "y": 60, "w": 160, "h": 140 },
  "checkpoints": [{ "x": 700, "y": 420 }],
  "rects": [{ "kind": "ground", "x": 0, "y": 640, "w": 400, "h": 200, "material": "cloth" }],
  "ropes": [{ "anchor": { "x": 720, "y": 120 }, "segments": 8, "segLen": 38 }],
  "seesaws": [], "crates": [], "fading": [], "springs": [],
  "deathY": 1040,
  "par": { "seconds": 90, "deathsPerPlayer": 2 },
  "replay": "replays/table-03.json"
}
```

`fading`（饼干平台）：`{ x, y, w, h, material?, on?, off?, phase? }`，在 `on` 秒、消失 `off` 秒（默认 3 / 2），`phase` 把这块的钟往后拨几秒；消失时抓着它的手一起松开。
`springs`（弹簧蜡烛）：`{ x, y, w, h, power? }`，身体落在顶上就弹，`power` 1 约弹 250 px（5 个身高）；侧面能抓。

每关必须附一个回放脚本（`replays/<id>.json`，每帧 4 人的 `PadInput`），`npm run levels` 用它无头跑通整关，用时在 `par.seconds` 的 0.5 到 2 倍之间才算合格。

关卡按 id 末尾的号排（table-01 … van-12，再 table-13 … van-24），彩蛋关最后。

### 机关（A6）

- `hazards`（碰到就死）：`{ x, y, w, h, kind?, dir?, players? }`。`kind` 是 `spike`（尖刺，默认）、`hot`（烫）、`zap`（电），`dir` 是尖朝哪边（默认 `up`）。身体、手、胳膊肘碰到都算。它不是碰撞体，不能站也不能抓，下面要垫台子。样子按世界画：桌上是竹签、红油锅、电热丝，温哥华是铁栅栏、夜市烤架、黄黑电轨；三种死法各有特效和声音，摔下去还是原来的水花。
- `movers`（会动的台子）：`{ x, y, w, h, path, speed, wait?, loop?, phase?, material?, deadly?, hazard?, players? }`。(x, y) 是起点，沿 `path` 的点来回走（`loop: true` 绕圈），`speed` 每秒多少像素（最多 600），每到一个点停 `wait` 秒，起步和停下都是慢慢的；站在上面、抓着它都跟着走。`deadly: true` 是碰到就死的块（`hazard` 定样子，默认电），不能抓。走到头停下的地方不能插进别的台子。
- `spinners`（会转的杆子）：`{ pivot, arms, len, h?, spin, phase?, material?, deadly?, players? }`。绕 `pivot` 转，`arms` 根（1 到 6）均匀分开，每根长 `len`（40 到 400）、粗 `h`（默认 16），`spin` 每秒转几弧度（正负 4 以内，正数顺时针）。能抓能站；`deadly: true` 的带刺，碰到就死。
- `players: [min, max]`（按人数摆）：`rects`、`ropes`、`seesaws`、`crates`、`fading`、`springs`、`hazards`、`movers`、`spinners` 里的每一件都可以写，只在 min 到 max 个人时摆出来，比如人少时多一块台子、人多时缝更宽。开局按人数摆，半路进人不重摆（下一局再摆），手机局的快照带 `np` 告诉手机按几个人摆。
- 会动的东西的位置只由关卡数据和时间算（`src/physics/motion.ts`），物理和画面用同一套，快照里不带它们。
- 复活的地方（起点，每个检查点，四个人错开站）离要命的东西至少 84 px。
- 机关样板关：开发页 `play.html?level=proto-02`（桌上）、`proto-03`（温哥华），不进大厅。

### 难关（C8）

- id 是 `table-13` … `table-18` 和 `van-19` … `van-24`，可以分批交；在的每一关都要过下面全部规则。
- `teaches` 是 `spike`、`hot`、`zap`、`mover`、`spinner`、`gauntlet` 之一，大厅里显示「难关：…」。每个世界最后一关（table-18、van-24）是 `gauntlet`，至少用四种机关。
- 大小、出生点、终点、检查点（每屏一个、15 到 60 秒一段、四个人都有落脚）和前 12 关一样；高过一屏的按攀爬关查（高 1400 到 2200，至少往上一屏）。
- `par.seconds` 60 到 240，`par.deathsPerPlayer` 2 到 8。
- 难在哪：要命的东西至少 4 处，每一屏（攀爬关每一层）都有；至少一个会动的台子或会转的杆子。回放里每个不要命的机关都真的用上（站上去或抓着至少 0.25 秒），每处要命的东西都在路上（有人到过 240 px 以内）。这关得靠大家：回放里真的有人连成串挂着（至少 0.25 秒）或者把队友丢过去，录好的每个手柄单独跑都过不去。
- 12 关到齐以后的搭配：能站能抓的动台至少 3 关，能抓的转杆至少 3 关，要命的动块至少 2 关，要命的转杆至少 2 关，尖刺、烫、电各至少 3 关，按人数变的至少 4 关，每个世界至少一道攀爬。
- 按人数变的关：1 到 4 个人里每一种摆法都要一份回放。4 个人那种是 `replays/<id>.json`，别的是 `replays/<id>.p<人数>.json`（这份回放就是那么多人）。`players` 范围现在要从 4 或更少开始；上限提到 6 个人以后再放开。

## 性能契约

主机页：4 人 + 40 个物体，2019 MacBook Air 的 Chrome 上 p95 帧时间 ≤ 20 ms。手柄页：首包 ≤ 50 KB，扫码到可按 ≤ 1 秒，CPU 空闲 ≥ 70%（电视局；手机局的画面包另外下载，见上）。
